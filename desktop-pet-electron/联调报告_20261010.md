## 一、联调方案（用什么通信）

**本地 WebSocket，单向推送。**

```
┌─────────────────────┐         ws://127.0.0.1:9876        ┌─────────────────────┐
│  LoveAI 主程序       │  ───────────────────────────────▶  │  Electron 桌宠      │
│  (PySide6)          │   {event, text, emotion, ...}      │  (renderer)         │
│                     │                                    │                     │
│  app/pet_ws_server. │   后台 asyncio 线程                  │  renderer/js/       │
│  py = WS 服务端     │                                    │  ws-client.js = 客户端│
└─────────────────────┘                                    └─────────────────────┘
```

- **服务端**：`app/pet_ws_server.py`（已存在），监听 127.0.0.1:9876，daemon 线程跑 asyncio loop。
- **客户端**：`renderer/js/ws-client.js`（已存在），桌宠启动自动连，断线 3 秒重连。
- **事件协议**（JSON，主→宠 单向）：
  | 事件 | 触发源（Qt 信号） | 桌宠行为 |
  |------|------------------|---------|
  | `hello` | 新连接握手 | 打日志 |
  | `thinking` | `analysis_progress` | 气泡显示"xx..."，切思考状态 |
  | `speaking` | `analysis_ready` | 气泡显示台词，嘴型动画，可选切表情 |
  | `emotion` | `affection_changed` | 更新好感度数值 |
  | `relationship_stage` | `analysis_ready.data.relationship_stage` | 顶部粉色标签"💕 暧昧期" |
  | `new_message` | `new_message` | 气泡显示"收到新消息，想想怎么回..." |

## 五、未解决的问题

1. **打包的 exe 是旧代码**：`dist/win-unpacked/resources/app.asar` 打于 02:12，但 `app.js`/`ws-client.js` 在 03:50 又改过。当前双击 exe 跑的是旧 renderer，立绘渲染空白。**需要重新打包**：`cd desktop-pet-electron; npm run build:win`。开发期用 `npm start` 跑当前源码已验证 OK。

2. **pet_launcher 优先 exe**：`app/pet_launcher.py` 现在优先找 `LoveAIPet.exe`。如果 exe 是旧的，主程序拉起来的就是旧桌宠。临时方案：开发期先杀 exe 再 `npm start`，或者删/移走 `dist/win-unpacked/` 强制 fallback 到 npm。长期方案：重新打包 exe。

3. **桌宠当前是沉浸式模式**：从截图看，桌宠以沉浸式全屏暗色模式启动（设置里保存了 immersive=true）。点右上角"✕ 退出"可切回角落小窗模式。这不是 bug，是上次的设置状态。

4. **桌宠退出不联动主程序**：当前主程序退出时不杀桌宠（桌宠托盘常驻，用户自己从托盘退）。设计如此，未来可加配置项。

## 六、怎么复跑

cd desktop-pet-electron
npm start

# 3. 重新打包 exe（解决旧 asar 问题）
npm run build:win
