## 三、关键设计决策

### 1. 生命周期托管策略
- 本启动器拉起的桌宠进程（记录 `Popen.pid`）**必杀**。
- 启动前已存在的 LoveAIPet.exe（旧独立使用场景）：默认纳入整体生命周期（`config.json` → `pet.lifecycle_tied=true`），退出时同杀；置 `false` 则保留。
- 退出顺序：先 `pet_ws_server.stop_server()`，再 `pet_launcher.stop_launched_pet()`；全程 try/except 错误隔离，绝不影响主程序退出。

### 2. 冻结态路径双兜底（关键工程点）
PyInstaller 6.x onedir 把 datas 落到 `_internal\`（不是 onedir 根）。因此：
- `pet_launcher._project_root()` = exe 同级目录（不变，满足验收点要求的 `_pet_dir()=<root>\desktop-pet-electron`）；
- `_find_packaged_exe()` 先查 `{app}\desktop-pet-electron\dist\win-unpacked`（Inno 分发首选），再兜底 `_internal\desktop-pet-electron\dist\win-unpacked`（PyInstaller datas）。两条路任一存在都能拉起。
- 实测构建产物：`dist\LoveAI\_internal\desktop-pet-electron\dist\win-unpacked\LoveAIPet.exe` 存在。

### 3. 共享配置协议
- 单一事实源：`config.json` 的 `pet` 段。
- 启动投影：`pet_config.write_shared_config()` 写 `data/pet_shared.json`（可写数据目录）。
- 传递：拉起子进程时注入环境变量 `LOVEAI_PET_SHARED=<path>` 与 `LOVEAI_APP_VERSION=<ver>`（开发态/npm 与冻结态通用，不依赖硬编码相对路径）。
- 桌宠读取：`settings-store.js` init 时读 `LOVEAI_PET_SHARED`，deepMerge 覆盖本地 userData 设置；文件不存在则回退本地。
- 上行：桌宠设置面板改 角色/音量/置顶/开机启动 → WS `{event:"config_update", data:{...}}` → `pet_ws_server` 白名单校验后回写 config.json pet 段 + 刷新共享文件 + 发 `config_changed` 信号。

### 4. 心跳与版本对齐
- 服务端每 15s 广播 `{event:"ping"}`；客户端 ws-client.js 收到即回 `{event:"pong"}`；服务端记录每客户端 last_seen，>45s 无上行则断开剔除。
- hello 事件携带主程序真实版本（config.json `app.version`=2.0.0）；桌宠连上后发 hello 携带自身版本（package.json 已对齐 2.0.0）；不一致打 warning 并下发 `version_mismatch`。

### 5. 打包避免重复
- spec datas 纳入 win-unpacked（使 onedir 自包含，验证 spec 有效）；
- iss 用 `Excludes: "_internal\desktop-pet-electron\*"` 排除 onedir 递归里的重复拷贝，桌宠由独立条目分发到 `{app}\desktop-pet-electron\dist\win-unpacked`，避免 285MB 桌宠运行包在安装目录内打两份。
