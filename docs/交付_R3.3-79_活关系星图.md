## 一、设计概览

```
                    ┌────────────── RelationshipGraph（services/relationship_graph.py）──────────────┐
                    │  center(目标对象) ──我↔NPC星形边──┐    家庭背景(family_context)                 │
                    │                                  ▼                                          │
                    │        NPC A ◄──NPC↔NPC边(strength/stance/relation_type)──► NPC B            │
                    │        · stance 节点立场(-1..1)     · faction 派系id                         │
                    │        · ethical_marks 伦理标记    · family 节点家庭(可选)                   │
                    │  compute_factions()：并查集聚类 → 反对派/助攻派/中立派 + 意见领袖(ALG-06)     │
                    └───────────────────────────┬──────────────────────────────────────────┘
                                                │ 活数据（influential_with_network）
                         ┌──────────────────────▼──────────────────────────┐
                         │  R3.3-77 桥接层：RelationshipTaskBridge(npc_task) │
                         │  方向A：NPC影响/派系立场/伦理标记/家庭背景 →        │
                         │         task_engine.add_custom_task（软任务，PRI_NPC=罗盘级）│
                         │  方向B：任务完成 → adjust_stance(+0.15) 立场回写      │
                         │         → NPC_STANCE_CHANGED / NPC_FACTION_UPDATED │
                         └──────────────────────┬──────────────────────────┘
                                                │
                    星图前端（relationship_graph_widget.py 最小兼容）：NPC↔NPC边着色、
                    派系外环、家庭小字标签、伦理琥珀点、点击摘要
```

- **数据层**：`FamilyContext`（family_structure/parents_status/siblings/atmosphere/evidence/manual，
  缺失一律"未知"不臆造）；`EthicalMark`（flag/label/risk_hint/opportunity_hint/evidence，
  **只做分析标记，无任何价值判断文案**）。
- **算法**：派系聚类用并查集（NPC↔NPC 边 strength≥0.35 成连接，≥2 节点成派系），
  派系立场=成员 stance 均值（≥0.2 助攻派 / ≤-0.2 反对派 / 其余中立派），
  意见领袖=|stance|×(连通度+1) 最大者（平局取 intimacy 高者），承接 ALG-06；ALG-07 的
  SNA 中心性/结构洞等高级指标列为遗留项（不跑偏）。
- **桥接层**：复用 R3.3-77 已建 `RelationshipTaskBridge`（name="npc_task"）增量扩展，
  不新建重复桥；新事件类型经 `services.bridges.events` 追加，未动 `__init__.py`。
- **决策契约**：`NpcState` 仅追加两个带默认值的新可选字段（faction/family_context），
  frozen contract 其余部分与 `boost_glide_planner.py` 一字未改；NPC 干扰项仍走
  `RelationState.npcs` + `_npc_drag` 的既有通道，任务注入路径不变。

## 三、数据流（真接线）

1. **建图**：`RelationshipGraph(center_id=...)`；`add_node` 建 NPC；`add_npc_edge` 建
   NPC↔NPC 边（strength/stance/relation_type）；节点 stance 按关系类型默认或 `adjust_stance` 调整。
2. **派系**：`compute_factions(min_strength=0.35)` → `factions`（fid → {label/stance/members/opinion_leader/risk_hint/opportunity_hint}）。
3. **家庭**：`set_family_dict(None, {...})` 手工录入图级（目标对象）家庭背景；
   `extract_from_chats` → 惰性调用 `persona_analyzer.extract_family_context` 自动提取；
   全缺失保持"未知"。
4. **伦理**：`mark_ethical(nid, flag, label, risk_hint, opportunity_hint, evidence)` 标记 NPC 节点。
5. **NPC→任务**：`influential_with_network()` 产出带派系/家庭/伦理的 NPC 摘要 →
   publish `NPC_INFLUENCE_CHANGED` → 桥方向A按关系类型+派系立场+伦理标记+家庭状态派生软任务
   （source: `bridge_npc_{rt}` / `bridge_npc_faction` / `bridge_npc_ethics` / `bridge_family`），
   全部走仲裁（PRI_NPC=罗盘级）与 `add_custom_task` 真实入 tasks 表；`_created[title]→{npc_name,nid}` 登记。
6. **任务→星图**：完成方向A创建的任务 → 桥方向B `adjust_stance(nid,+0.15)` 立场上修 →
   publish `NPC_STANCE_CHANGED`（before/after/delta）→ `compute_factions()` 重算 →
   publish `NPC_FACTION_UPDATED`（新派系快照）→ 同时保留原亲密度回写。
7. **可观测**：`network_summary()`（last_influence/created_tasks/last_stance_changes/last_factions）；
   `to_dict()` 全 JSON 可序列化，前端已布局图透传 family/ethical_marks/faction/faction_stance/stance。

## 六、集成验证发现的缺陷与修复（诚实记录）

并行开发期间桥接子代理自建测试子类（RichNPCGraph）验证，其数据形状与生产图改造后的真实形状
存在 3 处不一致，端到端演示（真实生产图）首次运行即暴露：
1. `get_factions()` 返回 dict（fid→派系）而非 list → 桥迭代到字符串 id 抛错；改为 values()/list 双态。
2. `ethical_marks` 是 EthicalMark dataclass（字段 risk_hint/opportunity_hint/label）而非带
   "kind" 键的 dict → 新增 `_field()` 双态取值（getattr + dict.get），兼容旧夹具。
3. `get_target_family()` 返回 FamilyContext dataclass → 改用 `_field()` 取 parents_status/family_structure。
修复后：pytest 17 passed、demo ALL PASS。**教训已沉淀**：跨模块并行开发须按冻结接口形状对接，
集成演示脚本作为验收闸门。

**第二轮（监工核查后）补测与修复**：
4. 覆盖缺口：test_r3379_npc_bridge.py 的 RichNPCGraph 子类恰好是 dict/list 形状，只覆盖了
   legacy 路径，桥的生产 dataclass 兼容此前仅由 demo 脚本验证、无 pytest 覆盖 → 新增
   tests\test_r3379_prod_shape.py（6 用例）用真实生产 RelationshipGraph（get_factions dict /
   EthicalMark / FamilyContext）双路径闭环。
5. 标题规格偏差：伦理任务标题此前拼的是 risk_hint/opportunity_hint 全文，与冻结规格（标题以
   label 短标签为主）不符 → 改为 label 为主、hint 括注（distinct 时 "label（hint）"），
   legacy dict 夹具不重复括注。修复后 23 passed、demo ALL PASS；最终合并回归 76 passed。
