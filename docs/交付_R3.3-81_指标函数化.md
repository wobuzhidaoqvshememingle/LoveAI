## 二、新推理层设计与数据流

### 旧机制（已废除）
`_KEYWORD_RULES` 字面子串命中 → 固定 delta（"想你"→intimacy+2.0、"嗯"→chat_resonance-0.5）。
同一句话在任何情绪/语境下得分都一样，是机械打分。

### 新机制（services/affection_reasoning.py，`AffectionReasoner`）
数据流：
```
消息 {content, direction}
  → ① 情绪读取 _read_emotion：优先用上游传入 emotion（0-1 标度）；
       缺省时本地 EmotionAnalyzer.analyze()（0-10 标度 ÷10 归一）
  → ② 姿态推断 _detect_postures：词只用于推断"关系姿态"这一中间结论，
       不直接加分。姿态集合：
       intimacy_declare(亲密表达)/investment_care(实际投入)/proactive_engage(接话)
       /compliance(顺从)/defiance(违抗)/conflict_negative(推开)/perfunctory(敷衍)
       /tsundere_playful(傲娇)/neutral_chitchat(无真实进展)
       并做语境冲突消解：傲娇压制"真冲突"、违抗压制"顺从"。
  → ③ 内心状态合成 _synthesize：delta = f(情绪valence, 姿态集合, 强度I, 方向factor)。
       每个姿态 → 内心状态(安全感/信任感/投入/亲密/被理解/被尊重) → 映射 18 维；
       顺从/违抗只动 loyalty，不污染好感。
  → ④ 产出 ReasoningReport：{dimensions:{18维→delta}, loyalty_delta, evidence:[],
       conclusions:[], summary}，每条带证据链。
  → ⑤ AffectionEngine.update_from_message 读报告替换各维 raw delta；
       analysis.affection_hints / loyalty_hints（LLM 提示）按 0.5 叠加（可选增强）。
```

### 为什么不是"关键词加分"
- 词只用于**推断姿态**（中间结论），最终 delta 由"情绪 valence × 姿态 × 强度 × 方向"合成。
- 同一词在不同情绪下 delta 不同/相反（见证据样本：love 语境"想你"→intimacy+1.98；
  cold 反话语境"想你？呵"→ trust-0.80、intimacy 不涨）。
- 分析结论为"无真实进展"（中性寒暄/敷衍）时 delta≈0，不再机械±0.5。
- 本地规则推理为基线（默认）；LLM 增强走 llm_gateway，可选、不强制、失败回退。

### 中心数据池约束通道（验收点4）
- 证据链用 `services.data_pool.contracts.Evidence` dataclass 承载（source/confidence/metadata），
  输入用 `Message`；与 `tests/test_data_pool_contracts.py` 同契约，可 to_dict/from_dict 序列化。

## 三、证据链格式示例

```
她说「想你了宝贝，我刚才路过你爱吃的那家店，给你点了份外卖留你家」
  → 她主动表达亲密/思念，内心在确认被爱与亲近，亲密关系前进
  → intimacy +1.98
```
三段式：**她说X → 推断她内心Y → Z维度Δ**，每条带 confidence（来自情绪置信度）。

**任务门禁证明**：积极回应"我对这家美术馆很感兴趣"→ `is_genuine_progress=True`（推进）；敷衍回应"兴趣？随便吧，无所谓"→ `is_genuine_progress=False`（命中"兴趣"关键词但不推进）。

## 七、已知限制（实事求是）

1. 本地规则推理为基线：姿态特征词表仍是人工维护的规则集，**不是**真 LLM 语义理解；复杂反讽/双关仍可能误判。LLM 增强通道已留（`llm_gateway` 注入、`affection_hints/loyalty_hints` 叠加），但本次未接入真实 LLM。
2. 情绪强度依赖上游传入：`update_from_message` 优先用调用方传入的 `emotion`；未传时才本地 `EmotionAnalyzer` 兜底（其关键词词典较粗）。
3. `recalculate_from_history`（历史重算路径，约 line 832）仍保留旧的统计式累加逻辑（含 `_KEYWORD_RULES` 残留引用），未整体切到推理层——本次改造范围是实时 `update_from_message` 链路；重算路径如切推理层需另立任务（避免一次性大改破坏既有重算口径）。
4. `_KEYWORD_RULES` 常量定义（约 line 250）与 `_build_reasons` 内约 line 524 的残留引用**仅用于拼"触发词展示文案"**（读已算好的 `applied` delta 做过滤，不反向参与任何打分）；且 `update_from_message` 实时链路已改用 `_build_reasons_from_report`，`_build_reasons` 不再被实时链路调用。即：残留不构成"字面关键词固定加分"，仅为未清理的死代码/展示文案，不影响分数。
5. `test_route_production_wiring.py` 因缺 PySide6（GUI 依赖）在本环境无法收集，非本次改动引入；未纳入回归。
6. 新增 `scripts_r3381_sample.py` 位于项目根目录，为证据复现脚本，可按需删除。
