**一致性处理**：每帧 prompt 均强制"完全保持同一人物身份、五官、黑长直发型、浅米色渐变背景、正面胸像构图、柔光布光，仅修改指定局部"；生成结果肉眼核对为同一人（已抽查嘴型/眨眼/表情三批）。帧间几何对齐靠统一 720×1080 输出 + PIXI 同锚点堆叠，交叉淡化误差肉眼不可辨。

### 三套动画的构成

1. **说话嘴型**：8 关键帧序列 `base→m01→m02→m03→m04→m03→m02→m05`，由 TTS 音频振幅 0..1 连续映射选帧，相邻帧 90ms 交叉淡化 → 等效 12+ 视觉位置的平滑循环（不再是 4 张跳切）。
2. **眨眼**：`base→eye_half→eye_closed→eye_half→base`，5 步步进，每步 35ms，单次 ~175ms，每 2.5~5 秒随机触发。
3. **idle 呼吸**：idle 时 `base↔breath_up` 正弦微混合（最大 28%，周期 3.2s），叠加 model-loader 已有的 Y 轴呼吸浮动与左右轻晃——纯数学插值，无跳切。

## 3. 播放逻辑与插值方案

- 新类 `PetFrameAnimator`（`renderer/js/pet-frames.js`）：只算"底图 A、顶图 B、混合比 mix"，不绑渲染方式。
- PIXI 角标/沉浸式共用同一条渲染面：`ImageCharacter` 内部维护两张同尺寸 Sprite（`_spriteA` 底、`_spriteB` 顶），每帧按 animator 输出切换 texture、`_spriteB.alpha = mix`。
- 帧模式自动启用：`model-loader` 检测到 cybergf `imagePath` 同目录存在 `frames/manifest.json` 即启用；失败自动降级旧单图路径。
- 优先级：说话嘴型 > 眨眼步进 > 表情帧；表情切换走 90ms 淡入。

---

## 4. 情绪/语音联动接线（复用既有 WS 9876 事件，只动表现层）

- 说话：WS `speaking`/`ai_speak`/`speech_state` → 既有状态机 SPEAKING → `audioPlayer.sample()` 振幅 → `character.setMouthOpen(v)` → 嘴型循环；无音频时走既有 `updateSpeakingMouth()` 合成口型。
- 情绪：WS `emotion`/`speaking.emotion` → 既有 `applyEmotion()` → `setExpression(happy/surprised/thinking/sleeping)` → 对应表情帧淡入。
- 眨眼/呼吸：渲染器内自动调度，无需外部事件。
- Python 侧 `pet_animator.py` 新增 `mouth_open`(0..1)、`blink_phase`(0..1) 连续量，供连续帧渲染插值；既有离散 `mouth`(a/i/u/e/o)、`eyes`(open/closed) 行为完全保留。

## 5. 性能验证

### 计算估算（静态）
- GPU 纹理内存 = 13 帧 × 720×1080 × 4 字节 ≈ **38.6 MB**（目标 <200 MB，余量充足）。
- CPU：每帧仅做 1 次纹理指针切换 + 1 次 alpha 赋值，无逐帧像素运算；帧循环为纯数学（正弦/三角波）。目标 <5% 可达。

### 实跑验证（离屏冒烟，非用户窗口）
- 用项目自带的离屏 BrowserWindow（`show:false`，不弹窗）加载新 `ImageCharacter` 跑 3.5 秒：
  - `[image-character] 连续帧模式启用`；
  - `frameMode = true, frames = 13`（13 帧全部加载成功，0 失败）；
  - 截图肉眼确认：新写实真人形象正确渲染居中、无白屏/报错。
- **未做**：长时间驻留实测 CPU%/内存 MB（不主动弹窗打扰用户当前使用）。上述 CPU<5%/内存<200MB 为**基于纹理占用与每帧开销的估算**，非实测读数。
