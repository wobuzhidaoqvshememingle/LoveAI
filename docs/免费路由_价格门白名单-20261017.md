## 1. 一句话结论

免费路由的候选池现在是一道**默认拒绝**的硬闸：**任何候选要进池，必须满足下面
(A)(B)(C) 三条之一；三条都不满足的，一律拒绝**，并打一条可读的 warning 告诉用户
「怎么把它加进白名单」。

```text
(A) builtin_free   —— 内置本机/零配置直通源（不产生第三方计费），直接放行
(B) proven_free    —— 正面证据证明免费：公开价格目录五维全 0，或 id 以 ":free" 结尾
(C) trusted        —— 用户把它显式登记进 llm.free.trusted_models（自担风险的声明）
    其余 → default_deny / endpoint_not_local  → 拒绝
    例外：proven_paid（正面证明付费）优先级最高，白名单也不得翻案
```

判定的唯一权威实现在 `services/free_model_router.py::FreeModelRouter.price_gate_verdict()`
（顺序不可颠倒）：

```python
prov = (provider or "").strip().lower()
mid = str(model or "")
if mid and mid in self._proven_paid_ids(prov):          # 1. 正面付费证据 → 拒绝（最高优先级）
    return False, "proven_paid"
if _builtin_free_allowed(prov, base_url):               # 2. (A) 内置直通源
    return True, "builtin_free"
if mid and (mid.endswith(":free") or mid in self._proven_free_ids(prov)):
    return True, "proven_free"                          # 3. (B) 正面免费证据
if mid and self._trusted_pattern_matches(prov, mid):
    return True, "trusted"                              # 4. (C) 显式白名单
if prov in BUILTIN_FREE_PROVIDERS:
    return False, "endpoint_not_local"                  # 5. 名字是内置源但地址不在本机
return False, "default_deny"                            # 6. 默认拒绝（fail-closed）
```

这道门在 `candidates()` 的**出口最后一步**统一执行（不是分散到各来源），
因此 `ranked()` / `chat()` / `routing_snapshot()` / `health_report()` 看到的
候选**全部**是过了门的，被拒的候选既不进池、也不产生任何出站调用。

## 2. 白名单配置键

| 项 | 值 |
| --- | --- |
| 键名 | `llm.free.trusted_models` |
| 类型 | 字符串（普通配置项，用户可见、可查、可改） |
| 分隔符 | 英文逗号 `,`、英文分号 `;`、中文逗号 `，` 均可；容忍空白与空项 |
| 生效范围 | `FreeModelRouter` 的价格门（(C) 路径） |
| 默认值 | 空（= 不放行任何「没有免费证据」的候选） |

### 2.1 取值格式（三种写法）

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| `provider:id` | **精确登记**某渠道的某个模型 | `nvidia:meta/llama-3.3-70b-instruct` |
| `provider:*` | 登记**整个端点**（该 provider 下所有 id 视为已确认） | `custom:*` |
| `id`（裸 id） | 任意 provider 都匹配该 id | `workbuddy/glm-5.3` |

- `provider` 必须取自路由已知的 provider 名（**共 20 个，完整清单与判定见 §2.3**）。
  写出别的名字时，整条按**裸 id** 处理（不会当 `provider:` 前缀解析），
  并且会打一条可自修复的 warning —— 同样见 §2.3。
- 只有「已知 provider 名 + 冒号后非空」才当 `provider:` 前缀解析 —— 这样自带冒号的
  id（如 `meta-llama/llama-3.3-70b-instruct:free`）不会被截断。
- **裸 `*` 不生效**（必须写成 `provider:*`）：防止一个星号把全世界放进来。
- 重复条目自动去重，顺序即配置顺序。

### 2.2 配置示例

```ini
# 场景一：把 NVIDIA 的某个 NIM 免费额度模型放行（NVIDIA 不公开价目表）
llm.free.trusted_models = nvidia:meta/llama-3.3-70b-instruct

# 场景二：信任自建/本机代理端点上的全部模型
llm.free.trusted_models = custom:*

# 场景三：混写（精确 + 端点级 + 裸 id 都支持，逗号/分号/中文逗号皆可）
llm.free.trusted_models = nvidia:meta/llama-3.3-70b-instruct; custom:workbuddy/glm-5.3，gpt-4o-mini
```

### 2.3 未知 provider 前缀条目会发生什么（D2）

- 前缀不在已知集合里（如 `foobar:*` / `foobar:gpt-4o`）时，整条仍按**裸 id** 处理（语义未变）：
  `"*"` **不生效**、只按字面匹配模型 id —— 实务上等于**什么都不放行**。但它**不再静默**：
  解析时会打一条 warning（同类条目**一个进程只打一次**；改了拼写会重新告警，进程重启后重新告警），
  提示里带**完整已知 provider 列表**，便于就地自修复；不抛异常、不打断启动：
  `白名单条目 "foobar:*" 的 provider "foobar" 不在已知 provider 集合内，已按「裸 id」处理、"*" 不会生效（若你本意是 provider 前缀，请核对 provider 名拼写）；已知 provider: <20 个名字>`
- **不告警的例外**：后半不是 `*` 且前缀含 `/` 的条目（如 `meta-llama/llama-3.3-70b-instruct:free`）
  —— 那是本仓库合法的带冒号裸 id，报它只会刷屏。
- **已知 provider 集合 = `KNOWN_PROVIDERS`（内核已知）∪ `PROVIDER_IDS`（10 个需 key 渠道名），共 20 个（差集已核验为空）**：
  `ollama` / `local_bridge` / `local_scan` / `custom` / `desktop` / `openrouter` / `nvidia` / `pollinations` / `llm7` / `browser_ai` /
  `sambanova` / `zhipu` / `github_models` / `cloudflare_workers_ai` / `groq` / `cerebras` / `cohere` / `google_gemini` / `mistral` / `huggingface`

## 3. 生效优先级（不可颠倒）

```text
proven_paid（正面证明付费）   >   (A) builtin_free   ≈  (B) proven_free   ≈  (C) trusted
        拒绝                            放行                                       放行
```

1. **正面付费证据最高**。公开价格目录里该 id 的 `prompt / completion / request /
   input_cache_read / input_cache_write` 任一项解析出非 0，就是「已证明付费」，
   直接拒绝 —— **即使它已经登记进白名单**（连 `provider:*` 端点级白名单也不行）。
   理由：白名单是用户对自己风险的声明，不能覆盖客观价格事实；`id` 以后从免费转收费
   时，这条规则会自动把它踢出去。
2. (A)(B)(C) 三条是并列的放行条件，任一条满足即放行。
3. 三条都不满足 → `default_deny`（默认拒绝）。
4. 特殊情况 `endpoint_not_local`：provider 名属于 (A) 表里「地址来自配置/运行时」的
   那几个源（`ollama` / `local_bridge` / `local_scan` / `desktop`），但它的
   `base_url` 并不在本机/内网 —— 此时**不算 (A)**，同样落到默认拒绝（可用白名单救回）。

### 3.1 原因码表（warning 里会打出来）

| 原因码 | 含义 | 是否可被白名单救回 |
| --- | --- | --- |
| `proven_paid` | 公开价格目录正面证明收费（任一项非 0） | **否**（硬闸核心） |
| `builtin_free` | (A) 内置本机/零配置直通源 | ——（已放行） |
| `proven_free` | (B) 目录五维全 0，或 id 以 `:free` 结尾 | ——（已放行） |
| `trusted` | (C) 命中白名单 | ——（已放行） |
| `endpoint_not_local` | 名字是内置本机源，但 base_url 不在本机/内网 | 是 |
| `default_deny` | 其余：没有拿到任何免费证据 | 是 |

## 4. 为什么默认拒绝（fail-closed）

免费路由的**第一原则是「不产生意外费用」**。上一版（R3.6）的口径是
「只有拿到**正面付费证据**才拒绝，证据不足就放行」——这在两条路径上等于把闸门留了
一条缝：

1. **NVIDIA 显式配置分支**：`llm.free.nvidia_key` + `llm.free.nvidia_models` 走同一道闸，
   但 NVIDIA 的 `/v1/models` **响应里根本没有 `pricing` 字段**，永远拿不到正面付费
   证据 → 写进配置的任意模型名都会被放行（一旦那个名字其实是收费模型，调用一次就是
   一次真实计费）。
2. **custom / 自建端点**（`llm.free.custom_base` + `custom_models`）：任意 OpenAI 兼容
   端点没有公开价目表 → 同样拿不到证据 → 放行。用户甚至可以把 `custom_base` 指到
   某个公网付费 API。

「拿不到证据」恰恰是**最需要小心**的情况，把它默认当成「免费」就是把未知风险当成了
零成本。所以口径翻转为：

> **不知道它是否免费 = 不放行**；只有 (A) 明摆着不产生第三方计费、(B) 有正面免费证据、
> (C) 用户自己显式声明「我知道我在放行什么」这三种情况才放行。

### 4.1 本次一并堵掉的同类路径

除了任务点名的 NVIDIA 与 custom 两条，复查时发现 **(A) 表里有四个 provider 的
`base_url` 来自配置或运行时**，光看 provider 名不足以证明「不产生第三方计费」：

| 路径 | 原口径 | 现口径 |
| --- | --- | --- |
| `llm.free.ollama_base` 指向公网付费端点 | 按 `ollama` 名放行 | 地址不在本机 → 拒绝（`endpoint_not_local`） |
| `llm.free.bridge_probe_urls` 指向公网端点 | 按 `local_bridge` 名放行 | 同上 |
| 本机扫描（`local_scan`）结果里的远端 base_url | 按 `local_scan` 名放行 | 同上 |
| 桌面 shim（`desktop`）的非回环 base_url | 按 `desktop` 名放行 | 同上 |

地址判定用 `_is_local_base_url()`：只认回环（`localhost` / `*.localhost` / `127.x` /
`::1` / `0.0.0.0`）、RFC1918 私网（`10.` / `192.168.` / `172.16-31.`）、link-local
（`169.254.` / `fe80::/10`）、ULA（`fc00::/7`）、`*.local`。**拿不到 host（空串、相对
路径、畸形 URL）一律按「不是本机」处理**（同样 fail-closed）。

`pollinations` / `llm7` 不在此列：它们的 `base_url` 由本模块**硬编码**
（`_ZERO_CONFIG_API`），用户改不了指向，所以按名字放行即可。

### 4.2 已知边界（如实记录，未做）

- `local_scan` 扫到的**本机端口的服务内部**会把请求转发到哪里，本模块无法验证
  （例如本机跑着一个把请求转卖给付费上游的代理）。当前的判定只到「地址是本机/内网」
  这一层 —— 这是本机扫描/桌面 shim 这一类通道的固有边界，不在本模块可观测范围内。
- `browser_ai`（浏览器 AI 兜底）不在价格门管辖内：它默认关闭，只有用户显式开启
  `browser_ai.enabled` 才会启用，且走的是「浏览器里的免费网页额度」而不是 API 计费；
  本模块不为其做价格证据判定。

## 5. 设置页 / 诊断脚本可见性

白名单必须**看得见**，所以它同时被追加进 `routing_snapshot()["mode"]`：

```json
{
  "mode": {
    "free_only": true,
    "fail_closed": true,
    "price_gate": "fail_closed_whitelist",
    "trusted_models": ["nvidia:meta/llama-3.3-70b-instruct", "custom:*"],
    "trusted_models_count": 2
  }
}
```

- `price_gate`：当前价格门模式标识（固定 `fail_closed_whitelist`）。
- `trusted_models`：白名单**原文条目清单**（按配置顺序，去重后）。
- `trusted_models_count`：条目数。
- 原有两个键 `free_only` / `fail_closed` 含义不变（纯追加，不改旧字段）。
- `channels` 里出现的通道**只可能是过了价格门的**，因此「快照里的通道数」
  = 当前真正允许出站的通道数；被拒的候选不会出现在快照里，
  但会在日志里留下 `已拒绝（fail-closed 价格门 <原因码>，默认拒绝）` 的 warning。

## 6. 被拒时的 warning 长什么样

```text
免费通道 nvidia:openai/gpt-4o 已拒绝（fail-closed 价格门 default_deny，默认拒绝）：
没有拿到任何免费证据（公开目录未覆盖 / 目录拉取失败 / 该端点不公开价目表）；
如确认其确为免费，请把 id 加入白名单配置项 llm.free.trusted_models 后重试
（写法：provider:id / provider:* / 裸 id）
```

- 同一条 `provider:model` **只告警一次**（去重集合与旧 `_reject_proven_paid` 共用），
  不会因为每次 `candidates()` 都刷屏。
- `proven_paid` 的提示语是「公开价格目录已证明它收费（pricing 任一项非 0），
  白名单也不得翻案」；`endpoint_not_local` 会点明是 `ollama_base` /
  `bridge_probe_urls` 这类地址被指到了公网端点。

## 7. 用户该怎么做（操作手册）

| 现象 | 处理 |
| --- | --- |
| 日志说「已拒绝（fail-closed 价格门 default_deny）」 | 确认该模型/端点确实免费后，把 `provider:id`（或 `provider:*`）写进 `llm.free.trusted_models` |
| 日志说「已拒绝（fail-closed 价格门 endpoint_not_local）」 | 检查 `llm.free.ollama_base` / `llm.free.bridge_probe_urls` / 扫描结果里的地址是不是本机；若确实要连远端免费端点，登记白名单 |
| 日志说「已拒绝（fail-closed 价格门 proven_paid…白名单也不得翻案）」 | 不要白名单它：该 id 已被公开价格目录证明收费，换一个真免费的模型 |
| 想收紧回「一个白名单都不放」 | 把 `llm.free.trusted_models` 清空即可（默认值就是空） |

> 说明：白名单是**用户自担风险**的显式声明，本模块不会去验证被登记项的真实价格
> —— 唯一的例外是「公开价格目录已经证明它收费」，那种情况白名单也不生效。
