## 2. 免费口径与 fail-closed

- **严格免费定义（五维）**：`STRICT_FREE_COST_KEYS = prompt / completion / request / input_cache_read / input_cache_write`，**五项全为 0 才算免费**；任一项非 0 / 缺失 / `None` / 空串 / 不可解析 → 不算免费证据。
- `mode` 恒含 `{"free_only": true, "fail_closed": true}`（本轮追加 `price_gate` / `trusted_models` / `trusted_models_count`）。
- **出站唯一拦网**：`candidates()` 是唯一候选来源，其出口对每个候选跑 `price_gate_verdict(...)`，不过门的不进返回列表并打同类只一次的 warning；`ranked()` / `chat()` / `probe_all()` / `routing_snapshot()` / `health_report()` 全部只消费 `candidates()` 的返回值。

## 3. 三处残余的处理结果（第一原则：不产生意外费用）

### 3.1 价格门残余 → 已改为「默认拒绝 + 显式白名单」硬闸

**改前语义**：`_proven_paid_pricing()` + `_reject_proven_paid()` —— 「**只有正面证据（解析出非 0）才拒绝；证据不足则放行**」。

**两处残余（独立验证方确认）**：
1. **NVIDIA 显式配置分支**：NVIDIA `/v1/models` 不返回 pricing 字段 → 永远拿不到正面证据 → 按旧语义**放行**。
2. **custom / 自建端点**（`llm.free.custom_base` + `custom_models`）：任意 OpenAI 兼容端点无公开价目表 → 无正面证据 → **放行**。

**改后语义**（唯一权威判据 `free_model_router.py::price_gate_verdict(provider, model, base_url=None)`，返回顺序即优先级）：

| 序 | 原因码 | 结果 | 判据 |
|---|---|---|---|
| 1 | `proven_paid` | **拒绝** | 公开目录已证明 pricing 任一项非 0 —— **白名单也不得翻案** |
| 2 | `builtin_free` | 放行 (A) | 内置本机/零配置直通源：`ollama / local_bridge / local_scan / desktop / pollinations / llm7`；其中除 `pollinations`/`llm7`（地址硬编码）外，**还须 `_is_local_base_url(base_url)` 为真** |
| 3 | `proven_free` | 放行 (B) | id 以 `:free` 结尾，或在目录里五维全 0 |
| 4 | `trusted` | 放行 (C) | 命中白名单 `llm.free.trusted_models` |
| 5 | `endpoint_not_local` | **拒绝** | provider 名是内置本机源，但地址不是本机/内网（**可由白名单救回**） |
| 6 | `default_deny` | **拒绝** | 其余一切，含「拿不到任何证据」 |

- **白名单**：配置键 **`llm.free.trusted_models`**；分隔符 `,` / `;` / `，`；三种写法 `provider:id`（精确）、`provider:*`（该 provider 全部）、裸 `id`；**裸 `*` 故意不生效**。解析函数 `_parse_trusted_entries`。
- **可见性**：`routing_snapshot()["mode"]` 追加 `price_gate="fail_closed_whitelist"` / `trusted_models` / `trusted_models_count`（追加式，旧键语义不变）。
- **复查外新增的第三条同类路径**：`ollama`/`local_bridge`/`local_scan`/`desktop` 的 base_url 来自配置或运行时，**借 provider 名把地址指到公网付费端点即可蒙混过关** → 新增 `endpoint_not_local` 原因码 + `_is_local_base_url()`（拿不到 host 一律判 False，fail-closed）。
- **实证**：① NVIDIA 分支塞 `openai/gpt-4o` → 0 候选、**出站 0 次**；② custom 塞 `gpt-4o` → 同上；③ 同候选登记白名单 → 进池并被调用（证明白名单非死代码）；④ 正面证明付费者即使 `openrouter:*` 也仍被拒（出站 0 次）；⑤ `ollama` / `pollinations` / `llm7` / OpenRouter `:free` 照常进池（不误杀）。
- **行为变更提示（封包线注意）**：这是**有意的默认拒绝**。用户原先靠"显式 config 且无付费证据"进池的 NVIDIA / custom 模型，现在需补一行白名单；旧测试里编码该语义的断言已同步改写（`tests/test_free_model_router.py`、`tests/test_free_router_failclosed_config.py`、`tests/test_free_router_kernel.py` 的 `mode` 整体比较改为逐键断言）。

### 3.2 渠道可达性判错 → 已重测改判 6 条

初次判定的因果写错了：把 Cloudflare 边缘返回的 `403` 当成"没收到响应"，据此判 `reachable=False` 并写"本机网络不通"。重测（每端点 2 轮，`curl -sS --ssl-no-revoke -m 8 -o body -D hdr -w ...`）后：

| id | 改前 | 改后 | 实测依据 |
|---|---|---|---|
| `groq` | False（"本机网络不通"） | **True** | HTTP 403 0.70~0.85s，`Server: cloudflare` + `CF-RAY: …-LAX` → **边缘真实应答，主机可达**，匿名/无 key 被拒 |
| `cerebras` | False（同上） | **True** | HTTP 403 0.64~0.73s，body `error code: 1009`，`CF-RAY: …-SEA` |
| `cohere` | False（同上） | **True** | 两处端点四次均 HTTP 403（34.96.76.122）|
| `github_models` | unknown | **True** | HTTP 200（`/inference/models`，body `OK`，140.82.114.22）；**可达≠可用**：无 PAT 不能验证推理 |
| `cloudflare_workers_ai` | unknown | **True** | HTTP 405（封套 `code 7001`）→ 服务端应答 |
| `hf_ssh` | False（"无公开 SSH 端点"） | **True**，且 `need_key` False→**True** | SSH 降至 `Permission denied (publickey,keyboard-interactive)`（服务端应答）；22 端口 `TcpTestSucceeded=True`。`benchmark-hf.co` 才是 DNS 不存在 |

**口径（已写进 `free_channel_catalog.py`）**：`True` = **收到任何 HTTP 状态码**（含 401/403/405/429）即主机可达，**匿名被拒 ≠ 本机网络不通**；`False` = 拿不到任何 HTTP 响应（超时 / DNS 失败 / 连接被拒 / TLS 失败）；`unknown` = 需 key 或登录态、端点不公开。

**仍未改判**：`google_gemini` / `mistral` / `huggingface` 仍为 `False`（多轮实测连接超时、**零 HTTP 响应** → 本机网络层不可达，**需代理**，不代表服务下线）；`browser_ai_hub` / `desktop_ai_connector` 仍为 `unknown`（需登录态、无公开端点）。

## 4. 已知不适用项：Sticky Session（本产品结构上不适用）

**裁定：(a) 结构上不适用**，同时满足 (c)：**它要解决的问题在本产品不存在**。

**核心证据（runtime 实证，打桩 LLM、不联网）**：
- `services/digital_twin.py` 的 `_build_system_prompt(recent_chats, affection, context_hint, snapshot)` 内 `chats_text = self._format_chats(recent_chats)`，并在返回的 system prompt 里拼成 `【最近聊天记录】\n{chats_text}` —— **对话历史每轮整段拼进 system prompt 字符串**。
- A1–A6 六条数字分身路径（`predict_reaction` / `simulate_reply` / `compare_options` / `predict_reaction_multi_scene` / `adversarial_debate` / `analyze_event_impact`）实测 system prompt 里 `【最近聊天记录】` 块**非空**。
- UI 聊天分析链（`analyze_chat` → `load_prompt("chat_analysis", chat_text=…)` → `llm.chat(system_prompt, chat_text)`）实测 `【聊天记录】` 块**非空**。
- `services/consult_engine.py` 第 2 轮实测命中 `之前的对话：`，含上轮问答。
- **出站形态**：永远是 `system_prompt + user_prompt` **两段字符串**，`messages` / `multi_turn` 恒为 `None` → `_resolve_session_key()` 恒返回空串 → **Sticky 取不到"第一条 user 消息"、也无从命中**。
- 机制侧实证：`messages=None, multi_turn=None ⇒ session_key=''`；`multi_turn=True ⇒ '45a97c3d…'`。

**结论的三条含义**：① Sticky 在本产品**无从生效**（不是漏接线）；② 因为历史在 prompt 里，**中途换模型不丢上下文、不出现格式不兼容** —— 它要防的"多轮体验断裂"在本产品不存在；③ 单轮/工具型调用（`recent_chats=[]`、`multi_dimension_analysis`、`tutorial_engine`）本就**不该**粘。

## 5. 需 key 渠道：状态与「填 key 即接入」的两步流程

**精确清单（10 条，判定口径 = `need_key is True` 且 `code_path` 曾写「未接入（仅登记）」）**：
`sambanova`、`zhipu`、`github_models`、`cloudflare_workers_ai`、`groq`、`cerebras`、`cohere`、`google_gemini`、`mistral`、`huggingface`

**已并入候选来源（R3.8）**：新增来源接入 `free_model_router.candidates()`，模型三级回退（显式 config > 动态目录 > 默认候选）借道 `_models_for()`，因此**产出自动经过出口价格门**；缺必填配置（如 cloudflare 缺 `account_id`）或 base_url 仍含 `{占位}` 的**整条跳过**；开关 `llm.free.keychannels.enabled`（默认 True）。
同时必须把 provider 名补进 `_TRUSTED_MODEL_PROVIDERS` 与 `_sort_group()` 的 remote 桶——**否则 `groq:*` 这种白名单会退化成裸 id 模式、静默失效；候选也会被排序阶段静默丢弃**（两处都是无报错的坑，已修并有回归护栏）。

### ⚠️ 双闸：光填 key 不会路由（这是刻意的，不是 bug）
这 10 条**都没有目录抓取器** → 价格证据集（`free_ids` / `paid_ids`）**恒空** → 逐条判据：`proven_paid` 不触发｜`builtin_free` 不触发｜`proven_free` 不触发｜`trusted` 只在显式登记时触发｜**以上皆非 → `default_deny` → 拒绝**。

- **填了 key、没进白名单 → 一个候选都不产（0 候选、0 出站）**。
- **填了 key + 白名单 → 才真正进池并被调用**（实证：`routes via groq:llama-3.1-8b-instant`，出站 base_url 与 model 均可核对）。

**可直接抄的两步（以 groq 为例）**：
```
第 1 步  llm.free.groq_key=<你的key>          （可选：llm.free.groq_models / llm.free.priority.groq / llm.free.limits.groq）
第 2 步  llm.free.trusted_models=groq:*        （只做第 1 步 = 依然 0 候选）
```

**为什么不能把「缺证据」当「免费」**：`sambanova` 的 `/v1/models` **实测每个模型 pricing 都非 0**。因为它没有抓取器，本模块「**没有拿到付费证据**」，它只靠 `default_deny` 被挡 —— 也就是说**它并不是被 `proven_paid` 拦下的，而是被「什么都证明不了」拦下的**。这恰恰是**不能把「缺证据」当成「免费」来放行的理由**：若按"反正没证据、先放行"处理，这个实测已证明**收费**的渠道就会混进免费池。

**自检能力**：`scripts/free_channel_keycheck.py --provider <id>` / `--all`（另有 `--probe-anonymous`）。对**已配 key 的渠道**发一次 `max_tokens=1` 的极小请求并打印 `可用/不可用/未配key｜HTTP 状态或异常类型｜延迟ms｜命中的 model`；**未配 key 不作为失败**；key 一律**掩码**显示。
**本轮实测结论：本机一条本批渠道的真 key 都没有 → 未做真实连通验证**（`--all` 输出 10 条全部「未配置 key（跳过）」、退出码 0）。为不留"脚本从未真的发过 HTTP"的盲区，另跑 `--probe-anonymous` 证明探测路径确实在发真实请求，并用**合成假 key** 验证了失败路径与掩码。**不许伪造成功** —— 本项如实记为「未做真实连通验证」。
