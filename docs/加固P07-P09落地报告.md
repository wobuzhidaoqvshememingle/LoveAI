## 三、已存在 vs 本次新增 vs 仍缺

### P-07
- **已存在（复用，未重写）**：`no_reply_detector.py` 的长冷/不回复结论（`detect_no_reply_scenario`，严重度"无/轻度/中度/重度/极端"）；`task_engine.adjust_tasks_for_state` 已有"回避/愤怒→暂停推进"雏形。
- **本次新增**：明确拒绝（强停止+要空间）+ 暗示拒绝（连续单字 / 话题反复转移 / 长冷）的统一判定；推进任务软暂停；分身话术边界降级。
- **仍缺（如实）**：上层编排（`analysis_orchestrator`）尚未在每轮消息后自动串起 `detect_refusal → task_engine.apply_refusal_downgrade → digital_twin.set_refusal_state`。该接线属"封包代理收尾后串行"范围，不在本次可改文件清单内，故只把可单测的能力落地、预留了调用入口。

### P-08
- **已存在**：无（原 `safety_filter` 仅为敏感词编码绕云审核，与"拒绝生成操纵话术"是两回事，未推翻）。
- **本次新增**：六类操纵红线命中即拒 + 真诚转述；分层知情同意 / 防依赖定位 / 隐私最小化工程证据 / 一键删除覆盖范围与备份策略文案。
- **仍缺（如实）**：① 一键删除的**真实物理执行**（连删衍生标签 / 向量索引 / 本地缓存）需对接 `memory_service` / `rag_service` / `backup_service`，不在可改范围；② `ManipulationRedlineGuard` 尚未在话术生成出口做强制串联（属封包接线）。以上文案与判定逻辑已可单测，执行侧未落地。

### P-09
- **已存在**：无。
- **本次新增**：身份证（含校验位）/ 手机号 / 银行卡（Luhn）/ 邮箱 / URL 的离线确定性检测、脱敏、三模式（mask 默认 / exclude / keep）。
- **仍缺（如实）**：① `chat_importer._save` 实际调用 `scan_messages` 的一行接线——`chat_importer.py` 不在本次可独占修改清单，未改；② 照片类 PII（依赖 OCR）不在文本正则覆盖范围；按任务要求"微信通路暂缓、PII 做到通用导入层即可"，未在微信解密上耗资源。
