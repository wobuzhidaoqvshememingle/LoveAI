### 1.2 其他值得知道的（P1/P2，详见子文档）

- 六维雷达图不要用默认 polygon，抄 Linear 风格：描边 1px、填充 10% 透明度、不要发光

### 方案 C：深夜书房暖琥珀（LoveAI 自研融合）

> 来源：**自己设计**。参考 Vercel Geist 极简骨架 + Arc 温暖感 + LoveAI 现有金色基因的"去廉价化"。
> **一句话氛围**：凌晨一点，一个人在暖台灯下翻聊天记录想事情，不是咖啡厅也不是机房。

#### 为什么是这个方向
- LoveAI 是恋爱**策略**工具，不能像 Linear 那样全冷
- 但也不能像 Arc 那样大渐变粉彩（那是浏览器，要好玩；策略工具要严肃）
- 当前金色 `#d4af37` 太饱和、像"土豪金"。改成**低饱和琥珀 + 玫瑰棕**，保留"金"的联想但去掉廉价感
- 底色从冷蓝黑改成**暖炭黑**（带棕调，不是蓝调）

### 我的建议（仅供参考，最终你拍板）

**推荐组合：C 是脸，B 是飘出去的壳，A 的纪律贯穿全局**

- **主界面 index.html：方案 C（暖琥珀）**——LoveAI 用户要长时间盯着看，Linear 冷蓝紫和"感情"零关联，Raycast 浮框范式不适合三栏高密度主界面。C 保留金色基因识别度，又去掉土豪金廉价感。
- **悬浮卡 chat_overlay.html：方案 B（Raycast 毛玻璃）**——悬浮卡本来就该"飘在其他窗口上面"，40px backdrop-blur 让它浮在微信上时有色调分离感。
- **咨询迷你窗 consult_mini.html：方案 C**（同主界面，轻度毛玻璃 20px）
- **3D 宠物 pet_3d.html：方案 C + 轻微回弹动效**——宠物是唯一允许"稍微可爱"的窗口，颜色跟琥珀/玫瑰走动效用 spring 回弹。
- **通用规范：方案 A 的纪律**（发丝边框、surface ladder、150ms 动效曲线）贯穿所有窗口。

**⚠️ 等你拍板**：是按上面 C+B+A 组合走？还是某一套单独做深？或者再出一套 D（如 Arc 粉彩渐变 / Claude.ai 米白底暗色反白）？

## 三、工程基建（打包 + 免费模型 + 故障转移）

> 完整报告见 `_round2_infra_research.md`（26KB）。

### 3.1 桌面打包：不换打包器，补三件事

LoveAI 现状是 PyInstaller onedir + Inno Setup，已经能跑。问题是安装包 ~2.5GB（onnxruntime + faster-whisper 模型全打进去了）。

**推荐做法**：
1. **核心包瘦身到 ~150MB**：Python 运行时 + PySide6 + 核心代码 + SQLite 驱动打进 Inno Setup 主包。
2. **重组件改按需下载**：whisper 模型、OCR 模型、Ollama 模型、知识库向量库，首次启动检测后从 CDN 拉到 `%APPDATA%/LoveAI/components/`，不打进主包。
3. **杀软误报**：代码签名是唯一真解（EV 证书 ~$300/年），不是换 Nuitka。Nuitka 编译成原生 exe 能缓解但治不了本。
4. **静默更新**：写 `latest.json` 放 CDN，客户端后台下载校验 sha256，提示用户重启即升级，不用重下整个包。

### 3.3 故障转移 / 成本优化

- **错误分级放宽**：429 阈值放宽到 100 次才切（不要一次就切）、404 阈值 0（立刻切）、5xx 阈值 5。按错误类型分设 allowed_fails。
