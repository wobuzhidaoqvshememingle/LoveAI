## 三、预建便携模型仓库（本次关键优化，免运行时 create）

**背景实证**：硬链接 preseed blob 为死路——`ollama create` 必走 llama-quantize 校验并另建 canonical blob（仍拷约 1.5GB），预置 raw blob 被忽略。运行时 create 在 8GB 机器上叠加磁盘与内存峰值，曾导致加载失败。

**做法**：
1. 在 E: 用**便携 ollama_runtime** 真机 create 两模型，删除未被 manifest 引用的原始上传 blob，得到就绪仓库 `<E盘>\LoveAI_build\portable_models\models`（8 文件 / 1534.2MB：15b canonical `sha256-098cb…`、05b canonical `sha256-969a…` + 4 配置 blob + 2 manifest）。
2. `scripts\collect_payload.py`：新增 `PORTABLE_STORE_SRC`（L69）、`collect_portable_store`（L295，main L354 调用）；`collect_models` 在就绪仓库存在时排除两个原始 GGUF（L198，源仓库文件保留不删）。
3. `tools\installer\LoveAI.iss`：新增释放规则（L74–78）到 `{app}\ollama_data\models`，Components=models、`onlyifdoesntexist`（升级不覆盖用户演进仓库）；[Dirs] 补 models 可写权限。
4. 运行时 `services\runtime_paths.py` `portable_ollama_env` 已设 `OLLAMA_MODELS={app}\ollama_data\models`，启动即读到两模型，`ensure_registered` 命中 present 跳过 create。

**体积**：安装包 models_local 由 2742→1208MB（−1534），新增 portable_models 1534MB，**净 ≈ 0**，单文件仍 2839MB、低于 Windows 4.2GB 上限（无需分卷）。
