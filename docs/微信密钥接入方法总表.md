**自动尝试顺序**（`extract_key_auto`）
```
per-db 缓存 → 全局 passphrase 缓存 → wx_key 日志 → 密钥记录文件
→ registry → process_args → (4.x) wechat_decrypt / (3.x) pywxdump
→ dump_rs → [仅 enable_high_risk=True] chatlog_alpha
```
每个候选密钥都过 `verify_key_sqlcipher4` / `verify_key_wxsqlite3` 校验，避免误判。

## 二、wx_key 原理拆解（源码级）

来源：`wx_key_src/dllmain.cpp`（开源项目 `ycccccccy/wx_key`，MIT）

```
DllMain(PROCESS_ATTACH)
  └─ CreateThread → MainThread
       ├─ EnumWindows 轮询，直到本进程有可见窗口
       ├─ GetModuleHandleA("Weixin.dll")
       ├─ setCipherKeyAddr = hWeixin + 0x4BBBC0     ← RVA，标注适配 4.1.2.11
       ├─ AddVectoredExceptionHandler(1, ...)
       ├─ VirtualProtect → *(BYTE*)setCipherKeyAddr = 0xCC   ← 下断点
       └─ 等登录

登录 → 微信调用 setCipherKey(key, len)
  └─ 触发 STATUS_BREAKPOINT
       └─ VectoredExceptionHandler
            ├─ pUnsafeData = pContext->Rdx        ← 立刻抓 RDX（密钥结构指针）
            ├─ CreateThread(KeyProcessorThread)   ← 耗时工作丢后台
            ├─ 恢复原始字节 + 卸载处理器 + Rip--
            └─ EXCEPTION_CONTINUE_EXECUTION
                 └─ KeyProcessorThread
                      ├─ keySize   = *[RDX + 0x10]
                      ├─ pKeyBuffer= *[RDX + 0x8]
                      ├─ 要求 keySize == 32
                      └─ hex 32 字节 → WriteLogToFile("KEY:" + keyHex)
```

**产出落点**：`%TEMP%\wx_key_status.log`（本机 `%TEMP%` = `<E盘>\Temp`）
**副作用**：结束时应调 `CleanupHook()` 自动卸载；**有干净卸载时「抓完必崩」不是必然**——异常退出才可能需要重启微信。
（2026-10-17 更正：此前写的「抓取完成后微信崩溃——设计内的，非故障」表述不准。）

**已适配版本**（源码 README）：4.1.2.17 / 4.1.2.16 / 4.1.2.11 / 4.1.2.9 / 4.1.1.19 / 4.1.0.34。
版本不支持时**不要**硬套 RVA，需换对应版本的 DLL。
> **2026-10-17 实测补充**：本机微信 **4.1.15.13** 在 `>=4.1.4` 档特征码上 **0 命中**
> （完整扫过 192.2 MB）；`<4.1.4` 档 1 命中，文件偏移 `0x5FE92F` → RVA `0x5FF52F` → 入口 RVA `0x5FF520`。
> 换微信版本（路线①）**禁止自行执行**；重编 DLL（路线②）需 MSVC，本机无；定稿＝只走缓存路线（路线③）。
> 详见《微信版本适配与已知限制.md》。

## 五、红线与注意

1. **注入动作不自动执行**。`services/collectors/pc/p9_frida_hook.py` 已固化：`available()` 只做**检测**（frida / wx_key.exe / 管理员权限 / 微信进程），`collect()` 绝不自动注入或运行 wx_key.exe。
2. **微信文件只读**。`E:\xwechat_files` 及其解密副本只读，不写入、不修改。
3. **密钥加密落盘**。机器指纹派生 AES 密钥，换机/换用户名后缓存失效需重抓。
4. **结束后自动卸载是正常路径**；异常退出可能需重启微信。（2026-10-17 更正：此前「抓取后微信崩溃属正常」的表述不准确。）
5. **封号风险**：注入与内存读取属于行为特征检测范围。低风险路线（registry / process_args / 记录文件 / 缓存）优先；注入类需用户明确知情后手动执行。
6. **Android root 路线**只适用于老版本（3.x 及更早）的 `EnMicroMsg.db`，4.x 手机端不适用。
