## 2. 判别口径：三句话

1. **路径字符串可以出现**（目录名、文件名出现在截图/日志/文档里，本身不构成泄露）。
2. **路径下的文件内容一律不许出现**（库本体、解密产物、密钥、明文、消息与联系人内容）。
3. **拿不准就当"内容"处理**：不放进包、不截进图、不贴进日志。宁可多剔一个目录，不要多带一个文件。

### 2.1 四条判别口径（64 位十六进制串到底能不能写进文档）

> 上面三句话管的是"路径与内容"；这四条管的是"**字符串形态**"。**两份口径都适用**，遇到 64 位 hex 一律按这四条判。凡交付物（本文档、《LoveAI 交付说明》、演示材料、日志模板）都照此执行。

1. **允许**：**文件指纹类** SHA256 / MD5 / 文件偏移 / 特征码 —— **前提是文中标注了"这是哪个文件的指纹"**。
   例：`Weixin.dll` 的 SHA256 `10f8e995…cb039de5`（本文档 §1.1 已标注为"文件指纹，非密钥"）→ **保留、不删**。理由：它是"**卡在 4.1.15.13、`>=4.1.4` 特征码 0 命中**"这组结论的**可复核证据**（201,552,944 B / 前缀 `10f8e995…` 可对上），删掉等于把结论降级成不可复核的口头断言。**一个已标注来源的文件指纹 ≠ 暴露面。**
2. **禁止**：任何**口令本体、口令派生物、密钥缓存值**的完整值 —— **明文、编码（base64 / hex）、或比"首 8 ＋ 末 4"更完整的形态**，一律不许出现在任何文档、日志、截图、报告、提交信息里。
3. **掩码形态全项目只此一种**：`首8位…末4位`（本文档统一为 `0795a409…cc22`）。**换写法**（这次首8末4、下次首4末4，或改用 `***` 之类）＝同一枚密钥在文档之间多出一个**可比对特征**，等于自己造暴露面。**只准这一种形态。**
4. **硬线不放松**：口令明文 **0 命中**（判据：小写与大写同时搜；针运行时从加密缓存取、脚本内不硬编码；本文档写完当场复扫，结果 0）。

## 5. 两条已采信结论（**原样保留**）

1. **止损重点在拷贝面，不是防整机。**
   —— 明文散落本机真正放大的是"**只丢文件不丢机**"的情形（备份盘、同步目录、共享目录、单文件提交、其它执行体读取）；"整机被带走"本来就等于全丢，此时明文散落与否几乎不改变结论。

2. **掩码只能降低后续扩散，召回不了已经落过的明文。**
   —— 掩码是"防新增 + 降扩散"，**不等于**密钥从未落过明文；若要求"从未落过"这一性质，则只能走密钥轮换，而轮换在本机**不可行**（生成权在微信侧、本机无法再抓取），代价与后果见《实测报告》§21.1。
