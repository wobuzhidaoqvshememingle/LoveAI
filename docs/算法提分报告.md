## 一、问题诊断：旧算法为什么是"贪心"

旧推荐路径 `TaskEngine.generate_recommended_tasks` 用 `_score_candidate` 给候选打分：

```
score = base × dir_w × strat_w × stage_w
```

这是一个**单步、静态、标量**打分：只看"这一步"候选与当前方向/策略/阶段是否匹配，完全不看该动作对未来、对主线终局的影响。结构性后果：

1. **步步对、结局错**：每一步都选当下分最高的动作，但可能把关系带向坏结局（如低 P 时硬推高价值动作）；
2. **不会处理冲突**：两个任务争抢同一时间/资源时没有"绕行"概念，只能硬推（失败→损伤）或跳过（任务未达成）；
3. **假设全知**：把对方内心当作可完全观测，不维护"对方真实意愿"的不确定性；
4. **无硬约束概念**：伤主线的动作只要当下分高就可能被选。

本步用一个长期优化决策核心替换该静态打分（旧方法保留为对照 A 组与降级路径）。

## 二、技术方案（严格数学主干）

算法本体使用严格数学语言：**SMDP / CMDP / MORL / HTN / POMDP**。钱学森弹道"助推-滑翔"、最小作用量、共振等**仅作命名修辞，不进算法本体**。

### 2.1 形式化总览

- **SMDP（半马尔可夫决策过程）**：对应小/中/主三级任务的多时间尺度。每个"选项（option）"动作 a 带持续时间 d_a，动作完成后状态才跳转，贴合"一个现实任务占用若干时间"。
- **HTN（分层任务网络）**：主线→中→小分解，用 `deps`（part-of/前置）描述，主任务在其前置完成前不解锁。
- **CMDP（约束马尔可夫）**：在 MDP 上加硬约束"主线不损"，伤主线动作在可行集里直接删除。
- **MORL / MO-MDP（多目标）**：奖励是多维向量，求帕累托非支配前沿，再用自适应权重标量化。
- **POMDP（部分可观测马尔可夫）**：对方内心为隐状态，维护信念分布 b，试探动作降低信念熵。

### 2.2 三状态量 P/M/A（可测代理，真实计算，ALG-01）

| 状态量 | 含义 | 可测代理（数据来源） |
|---|---|---|
| 势能 P | 吸引/好感/位势/信息充分度 | AffectionEngine 好感总分 `get_total_with_bonus` 归一化到 0..1 ＋ 信息完备度 |
| 势头 M | 好感趋势/对方主动投入度 | `get_history` 快照 total_score 的近期斜率 ＋ `get_proactive_ratio` 对方主动开启会话占比 |
| 对齐 A | 航向与主线吻合度 | DirectionCompass.evaluate 的 `alignment_score`（缺失时用 gates 结果兜底） |

三者均由现有引擎实时算出，不是手填常数。

### 2.3 长期值函数 Q/V（ALG-18，根治贪心）

对每个候选做有限视野的 SMDP 贝尔曼备份：

```
Q(s,a) = p_eff · w · r_a + γ^{d_a} · V̂( T(s,a) ; H − d_a )
V̂(s;h) = 有限视野前向 rollout：以"最大可行标量化奖励"为基线策略逐步推进，
          累积折扣即时奖励，末端加终端价值
V_term = 0.45·P + 0.35·M + 0.20·A − 负向 NPC 阻力
       + 0.6·(1 − 剩余主线/总主线)   # 主线完成度塑形
       − λ · detour_cost             # 迂回成本惩罚，主动选省时路径（λ=0.15）
```

- 有效成功率 `p_eff = success_prob · [(1−dep) + dep·(0.30 + 0.70·P)]`，`dep = 0.45·min(1, r_affection)`。语义：P 不足时高价值动作有效成功率被压低（先蓄势），P 足够才"释放"高价值动作。
- 状态转移（rollout 内真实更新）：
  - `ΔP = 0.6·p·r_aff + 0.4·p·r_trust`
  - `ΔM = 0.5·p·r_aff + 0.3·p·r_trust − 0.15·(1−p)`
  - `ΔA = 0.1·p·r_mainline + 0.05·mainline_impact`
- **视野自适应**：`H = max(ctx.horizon, min(Σ d_a, 40))`，保证迂回吃掉时间后仍有足够视野解锁 HTN 主链。
- **HTN 依赖感知塑形**：前置未就绪候选 `q −= 1.5`（现在做必失败）；就绪且能解锁他者 `q += 0.8·chain + 0.4·unlocks`。rollout 维护 done-set，完成即移出候选池并重算依赖，沿主链推进。

Q 值是真实多步递归/迭代算出，不是即时分冒充。

### 2.4 助推-滑翔四模式状态机（ALG-17）

按当前 P/M/A、冲突与候选判定模式并写入 `PlannedAction.mode`：

| 模式 | 触发条件 | 行为 |
|---|---|---|
| 变轨·迂回 diverge | 存在真实冲突（共享互斥标签）/ 负向 NPC | 在等价后继池绕行，航向不变、不掉势 |
| 俯冲·收口 dive | P≥0.58 且 M≥0.48 且 mainline_impact>0.2 且 p≥0.6 | 窗口成熟，高确定性任务一击达标 |
| 助推·蓄势 boost | P<0.48 | 先建吸引/信任/信息 |
| 滑翔·顺势 glide | P 足且 M≥0.38 且 A≥0.4 | 借势浅弧度推进 |

滚动循环：**感知 → 弹道分支（模式）→ 主线硬闸 → 执行更新 → 重新感知（MPC，ALG-34）**。
关键正确性：**有等价池但无冲突不再误判 diverge**（diverge 仅在真实冲突时触发），平坦路径不会白白付折扣。

### 2.5 CMDP 主线硬约束（ALG-47）

对每个候选计算闸门 `GateResult`：

```
passed  ⟺  mainline_impact ≥ 0  且  不超过剩余预算（time/energy/emotion/money）
```

`mainline_impact < 0`（伤主线）候选**一律从可行集否决，Q 再高也不选**。全部候选被否决时 `recommend` 返回空、`task_engine` 回退旧路径并记录，推荐不崩溃。

### 2.6 POMDP 信念状态（ALG-04）

- 维护对方真实意愿（接纳度等离散假设）上的概率分布 `BeliefState.distribution`，并计算熵与 confidence；
- 动作后按观测做贝叶斯更新；高 `info_gain` 试探动作在信念熵高时被优先选择以**降低不确定性**；
- 输出始终是概率分布，**绝不假设全知**，confidence 诚实标注、永不假定为 1。

### 2.7 冲突自由度扩展 + 迂回曲线达标（ALG-19 / ALG-27）

明确**不做"按优先级取舍 / 舍小家顾大家"**——冲突用来"消解"。规划器按**成本升序**枚举、取第一个可行方案，`heading_kept/momentum_kept` 恒 True：

| 顺序 | 类型 | 成本 | 语义 |
|---|---|---|---|
| 1 | equivalent 等价后继 | 0 | 换一个占用同一时段的等价动作绕开 |
| 2 | stagger 错峰 | +1 | 把相制任务在时间轴错开 |
| 3 | reform 重构 | +1 | 改变任务结构，使相制主线都被满足 |
| 4 | buffer 缓冲 | +2 | 仅当其余类型都无法化解时的最后手段 |

一个冲突只消解一次，后续步骤恢复 glide/dive，不连环叠加。结果写入 `PlannedAction.detour = {type, cost, path, heading_kept, momentum_kept}`。

### 2.8 多目标帕累托 + 权重动态（ALG-20 / ALG-21）

- 在 6 维目标向量（好感/主线/信任/对等投入/情绪安全/成长）上求**非支配前沿**；
- 标量化权重随状态自适应：蓄势期加重吸引/信任/成长，势头弱加重情绪安全，对齐差加重主线；
- `PlannedAction.pareto = {is_dominated, front_size, weights}`。
- 诚实说明：当前权重是**规则驱动的自适应**（随阶段/势头调整），尚不是从大批量结果中梯度学习得到。

### 2.9 其余决策能力

- **风险敏感 / 鲁棒（ALG-26）**：以 CVaR 简化版 `(1−p_eff)·负奖励幅度` 显式评估尾部下行风险；
- **心理适配（ALG-22）**：双主体画像（用户侧效能/控制点/认知风格，对方侧依恋/人格/定向）调节候选成功率；低效能用户长难动作打折、先小步赋能（串 ALG-23）。**已真实接线**：`task_engine` 把加载到的 persona 经 `build_decision_context(persona=...)` 映射为 `ctx.extras`，缺失/异常一律回退中性默认（0.5），不编造、不崩溃；
- **对手建模（ALG-25，简化可运行版）**：预测对方"读到我方动作后"的策略反应（如回避型对冒进动作成功率下调），乘入 p_eff；
- **延迟信用分配（ALG-36，骨架）**：记录每个动作"解锁了谁/对主线贡献"，`assign_credit` 按 直接解锁0.6 + 主线贡献0.3 + 自身0.8 归一化归因；
- **MPC 滚动重规划（ALG-34）**：每步用真实反馈重新 `recommend`，rollout 即重规划。

### 2.10 落点与接线（写了就挂载、挂载就连通）

- 共享契约：`services/decision_contract.py`（数据结构 + Policy 协议 + 固定落点）；
- 规划器：`services/boost_glide_planner.py`，类 `BoostGlidePlanner`，`__init__(config=None)`，方法 `decide(ctx)` / `recommend(ctx, top_n)`，以及 `build_decision_context(...)`；
- 接线点：`services/task_engine.py` 的 `generate_recommended_tasks`（约 1856–1890 行）：`build_decision_context → self._boost_planner.recommend → 以 Q 值排序并映射回任务字典`；异常或空结果回退旧 `_score_candidate`（旧路径完整保留）。已确认 `compass_result`、`persona` 在调用前正确赋值，不存在"因变量未定义而永远回退"的假挂载。

## 三、合成数据 Benchmark 设计（核心证据）

### 3.1 环境、配对与策略

- `benchmark/sim_environment.py`：确定性（可设 seed）关系演化环境，A/B 在**完全相同**场景中被驱动；策略只经 `DecisionContext / PlannedAction` 与环境交互，不可读环境内部；
- `benchmark/scenario_generator.py`：场景脚本 + 模拟聊天记录生成；
- `benchmark/policies.py`：
  - `GreedyPolicy`（A，name='A_greedy'）：忠实移植旧静态/短视决策——只按即时标量收益 argmax，不前瞻、不信念、不迂回（遇阻硬推→损伤，或跳过→未达成），注释标注与 `task_engine._score_candidate` 的对应；
  - B 组经 `decision_contract.load_planner()` 加载 `BoostGlidePlanner`；模块未就绪时返回 None、harness 不崩溃（不伪造 B）。

### 3.2 难度分级（easy / medium / hard）

难度不是"假装干扰不存在"，而是控制**客观条件有利程度 + 是否存在低成本化解路径**。所有参数对 A/B 对称生效、落盘可审计；干扰在各档都保留，只是强度/数量/视野不同。

| 难度参数 | easy | medium | hard |
|---|---|---|---|
| npc_count（通用 NPC 数） | 0 | 1 | 2 |
| npc_stance（立场，负=阻挠） | 0.0 | −0.5 | −0.7 |
| npc_influence（影响力） | 0.0 | 0.4 | 0.6 |
| conflict_pairs（相制任务对数） | 0 | 1 | 2 |
| has_incident（意外事件） | False | True | True |
| has_mutation（关系突变） | False | False | True |
| horizon_mult（视野倍率） | 1.5 | 1.15 | 0.75 |
| succ_floor（单任务成功率下限） | 0.90 | 0.80 | 0.60 |
| aff_gain_mult（正向好感增益倍率） | 1.25 | 1.0 | 0.85 |
| 标志性干扰 + 化解路径 | 轻度干扰 + 零成本 equivalent | 单个完整干扰 + 低成本 stagger/reform | 叠加干扰、紧视野、无廉价保证 |
| mutation 幅度 | 轻度（−3，快速修复） | 标准（−12） | 叠加（−12） |

说明：每个分类在 easy 仍保留"轻度"标志性干扰（不删除），但一定提供占用同一时段的 equivalent，使零折扣全达成客观可达；medium 保留完整单个干扰，提供 stagger/reform 低成本路径；hard 叠加多干扰且视野紧，允许明显残差。

### 3.3 十类场景

npc_rival（情敌）、mid_conflict（相制中任务）、npc_family（反对家人）、npc_wingman（闺蜜助攻）、incident（意外）、mutation（断崖突变+提前1步预警，ALG-09）、solvable（干净可解链）、cold_start（冷启动）、special_mainline（主线不损专项）、special_opposing（相背双任务都达成专项）。

### 3.4 "假聊天记录真注入"证明

场景生成 14 行中文聊天（sent/received + 真实时间戳），写入**临时 SQLite 的 `chat_messages` 表**，再用**真实 AffectionEngine** 重算：

```
proactive_ratio = 0.43, recalc_total = 54.1, stage = 5
```

证明注入是数据库级真注入并能驱动真实代理指标，而非字符串摆设。

### 3.5 指标口径

- **全任务达成率** = 完成目标任务数 /（小+中+主）目标任务总数；**整集100%达成比例** = 该场景全部目标任务完成的频率；
- 被 CMDP **正确拒绝的诱饵/捷径不是目标任务**，不计入未达成，单独记 `rejected_decoy`；
- **平均折扣 discount_steps**（零折扣=0）：按 detour.type 计——equivalent=0、stagger=+1、reform=+1、buffer=+2；A 不迂回恒 0；
- **主线损伤度**：硬推失败且 mainline_impact<0 时累加 |impact|；另记伤主线硬推次数、硬推总次数；
- **长期结局**：结局好感总分、关系阶段；**耗时**：单次决策 wall ms、整场景 wall ms；
- **显著性**：配对符号检验，H0 = P(B 优于 A)=0.5，精确二项双侧，平局剔除。

### 4.1 三档总览

| 指标 | easy A | easy B | medium A | medium B | hard A | hard B |
|---|---|---|---|---|---|---|
| 全任务达成率 | 1.000 | **1.000** | 1.000 | **1.000** | 0.465 | **0.558** |
| 整集 100% 达成 | 1.00 | **1.00** | 1.00 | **1.00** | 0.25 | **0.275** |
| 平均折扣 | 0.0 | 0.125 | 0.0 | 0.125 | 0.0 | 0.175 |
| 主线损伤度 | 0.105 | **0.0** | 0.105 | **0.0** | 0.138 | **0.0** |
| 硬推总次数 | 0.55 | 0.275 | 1.20 | 0.70 | 4.93 | 4.00 |
| 结局好感总分 | 74.06 | **75.62** | 64.97 | **68.16** | 19.55 | **26.55** |
| 结局关系阶段 | 6.90 | **7.12** | 6.00 | **6.35** | 1.50 | **2.30** |
| 单次决策 wall ms | 0.017 | 0.112 | 0.015 | 0.119 | 0.015 | 0.180 |

读法：

- **easy / medium：B 全部 100% 达成、近零折扣（0.125）、主线零损伤、好感 75.6 / 68.2、阶段 7.1 / 6.35**——直接满足"普通/有利条件近全达成、好感高、几乎不打折"的绝对水平要求。
- easy/medium 下 A 也 100% 达成（条件有利、且诱饵不计入分母），但 **A 主线损伤=0.105（选了捷径受伤）、B=0**，这正是 CMDP 硬闸的差异；B 好感与阶段也更高。
- **hard：条件确实恶劣（紧视野 0.75、2 NPC、2 冲突、意外+突变、成功率 0.6），允许明显残差**；B 仍在达成率（0.558 vs 0.465）、好感（26.6 vs 19.6）、阶段（2.3 vs 1.5）上一致优于 A，且主线零损伤（A=0.138）。

### 4.3 两个核心卖点专项

| 专项 | A 目标达成 | A 主线损伤 | B 目标达成 | B 主线损伤 | B 折扣 | B 好感 |
|---|---|---|---|---|---|---|
| mainline_under_pressure（主线不损） | 捷径受伤、目标链受损 | 0.60 | **目标任务全达成**、rejected_decoy=1 | **0.0** | 0 | 高 |
| special_opposing（相背双任务都达成） | 1/3（取舍/硬推） | 0.0 | **两相制任务都达成**再解锁主线 | **0.0** | 1~1.75 | 78.8~84 |

- **主线不损**：高压力/高诱惑下存在伤主线捷径（mainline_impact=−0.6），B 经 CMDP 硬闸**否决捷径、零损伤**，仍把 g1→g2→g3 目标链走完；A 选捷径失败即伤主线。
- **相背双任务都达成**：两个相制主线任务，B 经 reform/stagger **二者兼得**（不是"按优先级取舍一个"），再解锁主任务；A 只成其一或硬推失败。

## 七、仍存缺口（诚实，不夸大）

1. **权重"学习"是规则自适应**，尚非从结果数据中在线/梯度学习（ALG-21/37）；
2. **信用分配未闭环**：`assign_credit` 可算归因权重，但"延迟结果自动回流更新 V"的在线回路未接（ALG-36）；
3. **心理适配只覆盖效能+依恋两主轴**，控制点/认知风格等完整双主体画像矩阵未展开（ALG-22）；reform 只打标签、未生成"两个都满足"的具体重构文案（ALG-27）；
4. **NPC 仅单层活数据**：次级网络/派系（ALG-06）与 SNA 指标（ALG-07）未实现；
5. **反事实沙盘（ALG-28）、叙事一致性（ALG-33）、主线目标演化（ALG-38）、可变比率/ELO（ALG-45）未覆盖**；
6. **环境是合成假设**：转移概率/事件效果由人工设定，结论方向可信，但绝对数值不等同于真实用户表现；第三步可在真实联动数据上回测校准；
7. 全量测试套件（tests 下 150+ 文件）未逐一全跑；本步保证**新增与 task_engine 相关及受影响区域共 144 个测试全绿**。

## 九、结论

第二步已把任务线决策从"静态单步贪心"升级为"SMDP 长期值 + 四模式状态机 + CMDP 硬约束 + POMDP 信念 + 冲突自由度迂回 + MORL 帕累托"的可运行长期优化核心，并真实接线进 `task_engine`。
