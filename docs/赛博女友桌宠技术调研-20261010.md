## 1. 一句话结论

**优先走「live2d-py（原生 OpenGL）+ QOpenGLWidget 嵌入现有无边框窗口 + 音频振幅驱动口型」这条最短路径**，1 周内可出可玩 demo；序列帧路线先做透明合成修 bug 兜底；实时数字人（Wav2Lip/MuseTalk/HeyGem）**不要**做桌宠常驻，只适合"视频炫技页"。

## 3. 各方案展开

### 3.1 抖音"赛博女友"演示到底用什么做的？

扒了几条抖音热门演示（"星黎AI"、"CyberGf"等）和本地部署教程后，结论很清楚：

- **90% 是 Live2D 立绘**：右侧半透明精美女生立绘、眨眼、视线跟随、微表情（开心/生气/害羞）——这是 Live2D Cubism 的典型表现，不是实时面部驱动。
- **"口型同步好"的演示**：一部分是 Live2D 振幅驱动嘴部参数（看起来已经很自然）；另一部分真用了 Wav2Lip/MuseTalk 类数字人，但那些视频是**录屏演示**，要求观众有 NVIDIA 显卡，不是给消费级桌宠用户用的。
- **动作自然不僵硬**：Live2D 自带物理摆动（头发、衣服）、呼吸循环、视线跟随鼠标，这正是序列帧做不到的。
- **全屏暗色氛围**：那是应用层 UI，不是渲染技术问题，PySide6 做个暗色 QSS 就行。

**关键判断：用户要的效果 = Live2D，不是实时数字人。**

### 3.2 Live2D Cubism（推荐主路线）

#### 成熟度
- Live2D 公司成立 2006 年，Cubism SDK 已迭代到 5.4 Alpha（2026-07 发布），VTuber 圈、二次元游戏、桌宠圈事实标准。
- 官方 SDK 覆盖 Native(C++)、Web、Unity、Unreal、Cocos、Java、iOS、Android。**没有官方 Python SDK**。

#### Python 集成方案：live2d-py
- **仓库**：https://github.com/Arkueid/live2d-py （作者 Arkueid）
- **PyPI**：https://pypi.org/project/live2d-py/ ，`pip install live2d-py`
- **原理**：用 Python C++ API 封装 Live2D Native(C++)，自带预编译 wheel，**不需要自己编译 Cubism Core**。
- **兼容 UI 库**：官方声明支持 PyQt5 / PySide2 / **PySide6** / Pygame / GLFW / pyopengltk。
- **支持模型格式**：Cubism 2.1 和 Cubism 3.0 及以上（即 `.moc3` 新格式都能加载）。
- **自带能力**：视线跟踪、点击交互、动作播放、表情切换、物理摆动。
- **License**：live2d-py 本身开源（仓库 LICENSE），但它内部链接的 Cubism Core 遵循 Live2D Proprietary Software License——见下文授权。

#### 授权门槛（重点，决定能不能商用）
官方中文页：https://www.live2d.com/zh-CHS/sdk/download/native/

- **一般用户/小规模企业**：会计年度内销售收入 **< 1000 万日元（约 50 万人民币）→ 免授权费、免签合同**，可直接发布。
- 超过 1000 万日元后，需在次次月最后一天前通知 Live2D，追溯签约出版许可。
- 中型企业（<1 亿日元）：月费基础费 + 营收 5% 分成；大型企业（>1 亿日元）另算。
- **对 LoveAI（个人/小工作室）：现在和可预见的未来都免费**。
- 注意：**"可扩展应用程序"（允许用户自己装插件/模型）是例外条款**，即使小营收也要单独谈。LoveAI 如果开放用户导入自定义 Live2D 模型，需要重新评估；只内置官方 Sample 模型则无此问题。

#### 免费可商用立绘模型（直接拿来用）
Live2D 官方 Sample Data Collection（Free Material License）：
- **Shizuku**（Cubism 2.1，经典猫耳少女）——pixi-live2d-display demo 自带
- **Haru**（Cubism 4）
- **Hiyori / Mao / Miara**
- **Tororo & Hijiki**（猫）
- 下载页：https://www.live2d.com/en/learn/sample/
- 协议：Free Material License，可用于学习和商用产品（按官方条款署名）。
- **更精美的二次元模型**：nizima LIVE 商店（https://nizima.com）有大量第三方模型，付费几块到几百人民币，购买后可在自己产品里使用（看具体模型授权）。桌宠第一版先用官方 Haru/Hiyori 出效果。

#### 口型同步怎么做
官方文档：https://docs.live2d.com/en/cubism-sdk-manual/lipsync/

三档做法，**桌宠用第一档就够**：
1. **实时音量采样 → ParamMouthOpenY**（推荐）：TTS 播放时每帧取音频 RMS 音量，乘增益系数（约 2.0~2.5），clamp 到 0~1，`model.setParameterValueById("ParamMouthOpenY", value)`。再加一阶平滑（smoothing time ~0.1s）避免抖动。
2. 离线音素对齐：TTS 合成时拿到时间轴，逐帧写口型关键帧，更精准但工程重。
3. 实时 ASR 驱动：过度工程，桌宠不需要。

live2d-py 应该已经封装了 `setParameterValueById`，照着 pixi-live2d-display 的 JS 实现翻译即可（参考：https://www.s3lab.co.jp/blog/ai/3292/ ）。

#### 优点
- 立绘效果就是用户要的"精美二次元女生"。
- 原生 OpenGL 渲染，体积小（一个模型 ~10~30MB，Cubism Core dll ~几 MB）。
- 半透明窗口：QOpenGLWidget 本身支持 alpha 通道，配合 `Qt.FramelessWindowHint + WA_TranslucentBackground` 能做出真·透明桌宠（比 Qt3DWindow 的透明合成好控）。
- 表情/动作都是参数化的，LLM 返回情绪标签 → 一行代码切表情。

#### 缺点/坑
- live2d-py 是社区维护，issue 响应慢，遇到 Cubism 5 新格式可能踩坑。
- 需要自己写 QOpenGLWidget 的 paintGL/resizeGL 循环，和 Qt 事件循环整合（参考 PySide6 官方 threaded QOpenGLWidget 例程）。
- 打包 PyInstaller：要把 live2d-py 的 `.pyd` + Cubism Core 的 `.dll` + 模型资源一起收集，可能要写 `--add-data` 钩子。
- 透明合成：Qt 的 QOpenGLWidget 在 Windows 上默认不输出 alpha，需要在 `setFormat()` 里显式设 alpha buffer，且窗口属性要配对（见 3.6）。

### 3.3 QWebEngineView 嵌网页 Live2D（次选，出 demo 最快）

- **核心库**：pixi-live2d-display（https://github.com/guansss/pixi-live2d-display ），PixiJS 插件，1.4k+ stars，支持 Cubism 2.1/3/4。
- **思路**：写一个本地 HTML，用 pixi-live2d-display 加载模型，PySide6 用 QWebEngineView 加载这个 HTML。
- **和 Python 通信**：`QWebEnginePage.runJavaScript()` 双向调用，Python 告诉网页"现在切开心表情"，网页 JS 调 Live2DModel 方法。

#### 坑（必须知道）
- **透明背景在 Qt6 下是老大难**：要同时设
  - `view.setAttribute(Qt.WA_TranslucentBackground)`
  - `view.setStyleSheet("background:transparent;")`
  - `view.page().setBackgroundColor(Qt.transparent)`
  - 窗口必须 `setWindowFlags(Qt.FramelessWindowHint)`
  - CSS 里 html/body 也要 transparent
  - 即使全设了，Qt6 某些小版本仍会渲染成黑底，社区有 bug 报告（Qt Forum topic/162799）。
- **包体积爆炸**：PySide6-WebEngine 自带 Chromium，打包后 +150~250MB，对 LoveAI 这种已经要带 PyInstaller 的应用是负担。
- **启动慢**：WebEngine 冷启动 1~3 秒，桌宠一开机就出来会很违和。
- **性能**：Chromium 渲染 Live2D 没问题，但比原生 OpenGL 多一层。

#### 结论
**只适合"快速验证效果"，不适合最终交付**。可以用它 1 天出个 demo 给用户看效果，正式版换回 live2d-py 原生路线。

### 3.4 Spine 2D（不推荐 LoveAI 选）

- **官网**：https://esotericsoftware.com/spine-purchase
- **授权**：Essential $69 买断、Professional $379 买断，年营收 > $50 万才要 Enterprise。运行时（runtimes）开源。
- **对比 Live2D**：
  - Spine 是**游戏向骨骼动画**，强项是跑步/攻击/技能循环，不是"半身立绘+眨眼+口型+微表情"。
  - 日系二次元精美立绘生态几乎全在 Live2D 圈（nizima、官方 Sample、VTuber 皮）。
  - Spine **没有官方 Python/PySide6 绑定**，只有 Unity/Unreal/Godot/Phaser/PixiJS 等。要在 PySide6 里跑 Spine 得自己写 OpenGL 渲染 spine-runtimes 的 C 库，工作量巨大。
- **结论**：跳过。

### 3.5 实时数字人路线（Wav2Lip / MuseTalk / HeyGem / SadTalker）

这一挂是**照片级真人数字人**，用音频驱动一段真人视频的嘴部。先上实测数据：

| 模型 | 最低显存 | 实时帧率 | 音频→嘴部延迟 | 适合桌宠？ |
|---|---|---|---|---|
| Wav2Lip (256px) | ~6 GB | RTX 3060 上 ~60fps | ~217 ms | ❌ |
| MuseTalk (腾讯) | ~8 GB（fp16 可压 4~6GB） | V100 上 30fps+；RTX 3050Ti 上 8 秒视频要 ~5 分钟（离线） | ~443 ms | ❌ |
| SadTalker | 6 GB 最低，推荐 RTX 3060 12GB | **离线批量**，非实时 | 秒级 | ❌ |
| HeyGem.ai（硅基智能） | 1080Ti 8GB 最低，推荐 RTX 4070+32GB 内存 | 近实时但需 Docker/WSL2 | 1~2 秒 | ❌ |
| LatentSync 1.6 | ~18 GB | 慢 | 高 | ❌ |

#### 为什么不能做桌宠常驻
1. **硬件门槛**：必须 NVIDIA 独显 + CUDA。LoveAI 的用户群（普通 Windows 用户）很大概率没 N 卡或显存 < 6GB。桌宠是开机常驻的，不能要求用户有 RTX 3060。
2. **延迟**：端到端 1~2 秒（ASR 300ms + LLM 首字 300ms + TTS 300ms + 口型 150~450ms + 缓冲），对话感割裂。
3. **半透明窗口**：数字人输出的是矩形视频帧，背景是真人照片，**没法做 alpha 透明合成**——桌宠必须"浮在桌面上"，数字人会带个黑/白矩形方块。除非用绿幕抠像，又多一层开销。
4. **和 PySide6 集成重**：这些模型都是 Python+PyTorch 生态，要起一个推理服务（FastAPI/gRPC），PySide6 这边通过本地 HTTP 拉帧，再把 QImage 贴到 QLabel。架构复杂，内存占用 2~4GB。
5. **效果风格不对**：用户要的是"精美二次元立绘"，不是"真人视频头像"。抖音演示里那些很炫的数字人，是用来做短视频的，不是桌宠。

#### 什么时候才值得碰
- LoveAI 未来如果做"视频通话模式"（一键弹出一个全屏数字人和用户视频），那是另一个功能模块，用 HeyGem 或 MuseTalk 起一个独立进程。
- **桌宠立绘本身永远用 Live2D**。

#### 关键仓库（备查，不集成）
- MuseTalk：https://github.com/TMElyralab/MuseTalk
- HeyGem.ai：https://github.com/GuijiAI/HeyGem.ai
- SadTalker：https://github.com/OpenTalker/SadTalker
- Wav2Lip：https://github.com/Rudrabha/Wav2Lip

### 3.6 半透明无边框窗口 + 立绘的三条实现路对比

| 路线 | 透明效果 | 体积 | 性能 | 开发速度 | 主要坑 |
|---|---|---|---|---|---|
| **QWebEngineView + pixi-live2d-display** | Qt6 下透明不稳，可能黑底 | +200MB | 中（Chromium 开销） | 最快 | 透明 bug、包体积、冷启动慢 |
| **QOpenGLWidget + live2d-py** | 好（要显式设 alpha format） | +5MB | 最好 | 中 | OpenGL 上下文管理、PyInstaller 打包 .pyd/.dll |
| **现有 QLabel/Qt3DWindow + 序列帧** | LoveAI 现在就是这条，透明合成一般 | 最小 | 最好 | 已在做 | 序列帧僵硬、口型只能切两张图 |

**Qt 透明窗口三件套（任何路线都要）**：
```python
self.setWindowFlags(Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint | Qt.Tool)
self.setAttribute(Qt.WA_TranslucentBackground, True)
# 不要 setAttribute(Qt.WA_OpaquePaintEvent)
```
Windows 上 `WA_TranslucentBackground` 必须配 `FramelessWindowHint` 才生效（Qt 官方文档明确）。

## 4. 结合 LoveAI 现状的落地路线

LoveAI 已有资产：
- `app/qt3d_pet/`：Qt3DWindow 桌宠窗口（无边框半透明、拖拽、右键菜单、骨骼表情、气泡、眨眼定时器）——**透明合成效果一般**
- `assets/frames_female/`、`frames_male/`：序列帧 sprite（站立/左右转/闭眼/开心/生气/害羞几十张 PNG）
- `app/widgets/float_ball.py`、`chat_overlay.py`：悬浮球 + 聊天浮窗

### 第一阶段：序列帧优化（1 周内，不引入新技术栈）

目标：在不换 Live2D 的前提下，把现有效果拉到"能看"。

1. **修透明合成**：现在 Qt3DWindow 透明效果一般，换方案——把桌宠窗口从 Qt3DWindow 改成普通 `QWidget + WA_TranslucentBackground`，内部用 QLabel 序列帧轮播。Qt3DWindow 在 Windows 半透明合成上历史包袱重，序列帧根本不需要 3D。
2. **口型**：如果 `frames_female/` 里有"张嘴/闭嘴"两帧，TTS 播放时用 `sounddevice` 或 `pyaudio` 每 50ms 读一次音频 RMS 振幅，振幅 > 阈值切张嘴帧，否则闭嘴帧。30 行代码，效果立刻"会说话"。
3. **情绪帧切换**：LLM 返回情绪标签（开心/生气/害羞/中性）→ 切对应帧组。这个 LoveAI 已经有骨架。
4. **加待机微动**：随机间隔 2~5 秒播放一次"呼吸"帧或"眨眼"帧，避免呆立。
5. **暗色氛围**：聊天浮窗加暗色 QSS，右侧立绘窗口保持透明，背景透出暗色主界面。

**这阶段结束时用户能看到什么**：右侧半透明女生立绘、会随声音张嘴、能切表情、不僵硬到尴尬。够内测。

### 第二阶段：上 Live2D（2~3 周）

目标：达到抖音演示的"精美立绘+自然动作+微表情"。

1. **新建 `app/live2d_pet/` 模块**：
   - 用 `QOpenGLWidget` 子类化，`initializeGL()` 里 `live2d_py.LAppModel()` 加载模型。
   - 模型先用官方免费 **Haru** 或 **Hiyori**（Cubism 4，半身立绘，女生）。
   - 窗口复用第一阶段的无边框透明外壳，只是把内部 QLabel 换成 QOpenGLWidget。
2. **口型同步**：TTS 播放线程每帧读 RMS → `model.setParameterValueById("ParamMouthOpenY", rms*2.5)`。
3. **表情**：LLM 情绪标签 → `model.startMotion()` 或 `setExpression()`。
4. **视线跟随**：鼠标移动时，把鼠标坐标归一化到模型空间，写 `ParamAngleX / ParamAngleY / ParamEyeBallX / ParamEyeBallY`。live2d-py 应该内置了 hit area 和 focus 机制。
5. **物理摆动**：Live2D 模型自带，加载即生效。
6. **PyInstaller 打包**：用 `--add-data` 把 `live2d_py` 包里的 `.pyd`、Cubism Core `*.dll`、模型目录（`.moc3` + `.physics3.json` + `.motion3.json` + 纹理 PNG）一起打进去。
7. **fallback**：如果 live2d-py 在某台机器 OpenGL 初始化失败，自动回退到第一阶段的序列帧 QLabel。

**这阶段结束时**：就是抖音演示那种效果——精美立绘、会说话、表情丰富、动作自然。

### 第三阶段：才考虑实时数字人（不进桌宠主线）

- 只在"全屏对话模式"里做一个独立数字人窗口，用 MuseTalk fp16 + RTX 3060 以上机器可选启用。
- 桌宠主立绘永远保持 Live2D，因为它要常驻、要透明、要低配能跑。

## 6. 风险与注意事项

1. **Live2D 模型版权**：官方 Sample 可商用（Free Material License），但 nizima 买来的第三方模型要看具体条款——有些只允许个人使用，不允许打包进商业软件分发。LoveAI 第一版用官方 Sample，商用前再补授权。
2. **可扩展应用条款**：如果 LoveAI 开放"用户导入自己的 Live2D 模型"，触发 Live2D 的 Expandable Application 条款，即使小营收也要谈。第一版**只内置固定模型**，不开放导入。
3. **PyInstaller + live2d-py**：`.pyd` 依赖 VC++ Runtime，要确认目标机器有 VC_redist.x64.exe；Cubism Core 的 `.dll` 要和 `.pyd` 同目录。
4. **OpenGL 驱动**：个别老旧/虚拟机 Windows 机器 OpenGL 版本 < 2.1，live2d-py 起不来——必须做 fallback 到序列帧。
5. **不要被抖音视频骗**：那些"超逼真数字人赛博女友"演示视频是显卡发烧友录的，不是消费级桌宠。LoveAI 面向普通用户，**Live2D 就是正确答案**。
