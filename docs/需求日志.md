## 核心硬需求（每轮必查，一条不能少，用户原话为准，不自行扭曲）
1.  独立Windows exe，双击运行，不依赖豆包客户端，填入兼容OpenAI接口的API Key即可使用
2.  两个核心功能严格分流：
    a.  聊天记录分析模式：自动读取聊天记录，围绕实时性（当下该做什么）、连续性（承接之前聊的内容）、因时制宜（贴合对方当下情绪状态）给出操作建议和逐字可复制话术
    b.  纯情感咨询模式：对方不愿意共享聊天记录时，像心理咨询窗口一样直接接诊
3.  聊天记录导入方式全部支持：
    - 自动扫屏/录屏识屏（自动扫描微信聊天界面，不用手动导入）
    - 文件一次性导入（粘贴/txt/md文件）
    - 聊天截图上传（云端多模态识别）
    - 支持实时更新新消息
    - 支持用户口头补充说明
4.  好感度评分规则：有聊天记录时优先从互动频率、谁主动、回复速度打分，无聊天记录时再多维度综合评估；好感度是波动变化的，不是固定值，随每次互动动态更新；参考Galgame式关卡机制，好感度没到对应阶段绝对不能跳步
5.  自动收集学习用户平时的说话风格/表达方式，给出的回复贴合用户语气，不用用户不会说的书面词，不写AI腔
6.  每个建议必须附带概率预判：明确写出来这么做大概会产生什么结果，不同结果的发生概率、对应应对方式
7.  支持账单/消费记录分析：分析两个人的金钱付出比例，按"付出代价占自身可承受能力的比例"判断真心程度，不是只看绝对金额
8.  自动识别对方每句话的情绪状态，标注情绪变化曲线
9.  自动扩仓知识库：遇到没覆盖的新场景/新问题，自动联网检索最新内容补充进本地库；严格信息蒸馏，剔除男拳女拳极端对立、卖课鸡汤、PUA课程、过时老经验，只留可落地的真人实操经验和专业心理学知识
10. 敏感词自动实时替换，防止平台拦截/撤回
11. 用户反馈的有效经验自动沉淀回本地知识库，下次直接调用
12. 倒刺陷阱规则：每一个教用户做的动作，都必须同时写好退路——万一对方反应不对，怎么体面撤回、不尴尬、不被拉黑；绝对不写那种一步上去就下不来、发出去就收不回来的死教程
13. 先写完整操作教程，最后一段才提注意事项，绝不开头先讲风险劝退，绝不教用户放弃，所有问题都给可执行的解决方法
14. 自动区分用户描述里的主观滤镜和客观事实，不把用户的猜测当结论，不脑补
15. 所有程序文件、备份、数据全部存D盘，不占用C盘系统盘
16. 修改文件前必须整个文件夹全量备份，不是只备份核心文件，是整个项目文件夹（src/、knowledge/、assets/、所有配置文件、所有文档）全部复制到 backups/full-时间戳/ 目录；根存文件永远只读不直接改；改坏可整体回滚
17. 吵架模块：记录每次吵架原因与解决方案，下次吵架自动提醒别翻旧账，目标是共同解决问题、培养默契，不是争谁对谁错比输赢
18. 记忆分层缓存：平时只存关键词标签作为目录索引，特殊重要事件（吵架/确定关系/表白）才存完整对话原文；检索时先搜关键词命中再读完整内容，全部存在本地memory_cache目录不上云
19. 手段中立：所有心理学相关内容（包括灰色影响、黑暗人格识别）全收录，只做原理研究和识别防御，绝对不教长期伤害性、违法害人的落地教程
20. 本地skill为绝对主体：恋爱军师/情圣/情感写作工坊/亲密关系咨询四个本地skill是核心，所有开源模块都是工具层补充，不许破坏原有规则

## 最新UI需求（v4.0，以用户最新要求为准，之前所有迭代版本全部作废）

### 三窗口模式定位
1. **大窗模式 (1100×760) — 大型游戏首页质感**
   - 定位：大型乙游/MMORPG主界面质感，不是普通网页
   - 背景：必须用真实精美游戏风格背景图，不要纯CSS渐变
   - 所有UI元素（按钮、卡片）都要有一圈发光光晕边框（多层box-shadow），不是实线边框
   - 玻璃通透质感（backdrop-filter blur）
   - 参考风格：恋与深空主界面——深色星空+发光光晕+玻璃通透
   - 布局：顶部标题+左右两侧功能按钮组+中央角色展示区+底部导航
   - 禁止：圆形攻击技能键、照抄商城布局、浅紫奶白柔和风、5毛钱特效

2. **中窗模式 (720×540) — 全息烫金玻璃系统面板**
   - 定位：小说里的"系统"面板，全息玻璃质感
   - 底色：烫金色调半透明，不要蓝色
   - 边框：发光烫金纹理边框
   - 内容：好感度仪表盘、任务进度、技能列表
   - 要高奢感，不要科技蓝

3. **悬浮模式 (320×680) — 烫金薄纱玻璃盖微信**
   - 定位：烫金半透明薄纱玻璃，能透下面微信的字
   - 布局：左边栏=好感度/状态/任务进度，右边栏=情感咨询输入框
   - 自动捕获微信窗口位置，叠在微信右侧
   - 像"卡纸"一样贴在微信边上

## v4.2 核心设计原则（密钥链式工作流程解锁）

### 设计理念（用户亲口解释，最高优先级）
> "就像我之前主体的那个skill一样，它里面不是有密钥链工作流程解锁功能吗？要完成这一步，才能拿到下一步的密钥；下一步再照着那个密钥，继续解锁下一步。给的是技能树，指的就是这玩意。"

### 正确理解：密钥链式工作流程
**是后端工作流程要做成密钥链：一步扣一步，完成当前步→拿到密钥→用密钥解锁下一步。**

不是：好感度到了就自动解锁功能
是：完成上一步任务 → 获得密钥 → 密钥解锁下一步 → 下一步才能跑

就像技能树一样：
- 必须先点Lv1的技能，点满了才能点Lv2
- 不能跳过Lv1直接点Lv2
- Lv1的输出是Lv2的钥匙

对应到后端：
- **第一步**：基础聊天回复 → 跑通后输出第一个密钥
- **第二步**：拿到密钥1 → 解锁好感度计算 → 跑通后输出密钥2
- **第三步**：拿到密钥2 → 解锁情景识别 → 跑通后输出密钥3
- **第四步**：拿到密钥3 → 解锁任务生成 → 跑通后输出密钥4
- **第五步**：拿到密钥4 → 解锁阶段跃迁 → ...
- ...以此类推

每一步必须验证通过了，才能进入下一步。每一步的输出是下一步的输入/钥匙。

### 之前的错误
- 错误1：把"技能树"当成了前端UI功能，还做了skillModal弹窗 → 已删
- 错误2：理解成前端功能按钮按好感度解锁 → 错了，是密钥链式工作流程
- 错误3：一次性把所有后端模块全堆上去 → 违反密钥链原则

### 接下来要做
- 按密钥链顺序一步步验证：基础聊天 → 好感度 → 情景识别 → 任务生成 → 阶段跃迁 → ...
- 每一步跑通了再进下一步
- 不跳步、不堆功能

- 直接放大模型上下文窗口
- 作用：保持对话连贯（"这个""那个"指什么）
- 存储：内存环形队列

**第二层：长期记忆（LTM）**
- 存所有历史对话的embedding向量
- 需要时按相似度检索，只拿最相关的几条
- 作用：记住几个月前说过的话
- 存储：向量数据库（SQLite FTS5就够）

**第三层：核心事实记忆**
- 结构化存储用户固定信息：
  - 姓名、年龄、职业
  - 重要事件（什么时候分手、什么时候吵架）
  - 偏好（喜欢什么风格、讨厌什么）
  - 关键人物（NPD伴侣、孩子）
- 作用：不用每次都重新告诉AI
- 存储：JSON文件

### 核心流程
1. 用户说话 → 先判断重要性
2. 重要的信息 → 提取成结构化事实，存入核心记忆
3. 新对话进来 → 先检索相关的历史记忆
4. 把相关记忆 + 当前对话 → 一起发给大模型

### 好处
- 省token：不用把所有上下文都塞进去
- 记得久：几个月前的对话也能想起来
- 不遗忘：用户说过的重要信息永远记得

### 使用时：三级分层路由（src\ai\local_model.py route_level()）

| 档位 | 模型 | 干什么 | 触发条件 |
|---|---|---|---|
| L1 | smollm2-135m + loveai-core-v2 LoRA | 日常陪伴、情绪承接、撒娇 | 打招呼/想你/在吗/吃了吗（<15字，无分析关键词） |
| L2 | Qwen-0.5B + loveai-core LoRA | 本地深聊、简单情感问题、学说话方式 | 含"她/他/女生/追/约会"等中等复杂词 |
| L3 | hy4-preview（云端） | 复杂分析、策略、话术、长文本 | 含"分析/怎么办/为什么/聊天记录"，或>100字 |

拿不准 → 默认走云端（小模型容易胡说）。

### 训练时：蒸馏模式（src\ai\finetune.py）
**每晚3点自动跑，学生是 smollm2-135m，不是 Qwen。**

训练数据优先级（从高到低）：

| 渠道 | 来源 | 学什么 | 过滤 |
|---|---|---|---|
| A | chat_log 里 source='cloud-hy4' | 领导的高级分析、策略、概率判断 | 踢掉含"我不能/作为AI/建议咨询"的安全套话 |
| A2 | chat_log 里 source='qwen%' | Qwen 的表达方式、用词、逻辑（hy4 额度用完时顶上） | 同上过滤安全词 |
| B | knowledge\**\*.md（前50文件） | 情感知识、话术库 | 无 |
| D | crawler_feed.md | 外部爬取内容 | 无 |
| C | chat_log 里 source='smollm2%' | 学生自己说过的话（最低优先，最多50条） | 避免越学越歪 |

### 关键设计：无限制人设不被污染
hy4 是有审查的，它会说"我不能""作为AI"。这些**不能当教材**。
finetune.py 的 load_teacher_records() 里有 REJECT_PHRASES 列表，命中即跳过。
smollm2 学完之后：
- ✅ 会分析、会出话术（跟领导一样聪明）
- ❌ 不会拒答、不会讲安全套话（保持苏晚无限制人设）

## v1.0 发布硬性验收标准（2026-10-04 实测补充）

> 本节是 v1.0 打包发布前，通过"插数据包实测"（直接调后端函数，不看UI渲染）发现并修复的问题。以下为**硬性标准**，以后每次打包前必须逐条过。

### 两大核心功能定义（不许再含糊）

**功能1：游戏系统**——根据对话实时发布任务、实时更新好感度
- 必须调 `wsm.get_player_info()` 返回真实等级/经验/金币（不是静态默认值）
- 必须调 `wsm.get_quests()` 返回主线任务列表（m1发第一条消息、m2好感度到30等）
- 必须调 `wsm.generate_dynamic_tasks()` 根据当前好感度自动推荐动态任务
- 发消息后 `wsm.current_favor` 必须真实变化，不是UI上画死的50%

**功能2：情感咨询**——有问题直接问
- 在线（填了API Key）：`api_bridge.send` → `wsm.process_chat` → 云端大模型，必须真返回分析
- 离线（没填Key）：必须有兜底，不能直接报错卡死

### v1.0 实测发现并已修复的问题

1. **离线分支根本没调本地模型**——原来 api_bridge.send 第121行，没Key时直接返回硬编码关键词模板"在呢刚忙完"，smollm2一次都没被加载。已修复：离线时先试 `local_ai.chat(msg)`，失败再fallback模板。
2. **smollm2 生成缺 repetition_penalty**——原 generate() 只有 temperature/top_p，导致输出"苏晚说说苏晚说说..."无限循环。已加 `repetition_penalty=1.3, no_repeat_ngram_size=3`。
3. **本地输出中文质量门**——smollm2-135m 是135M小模型，训练不充分，实测输出过英文乱码（"What is the answer to this riddle?"）。已加质量门：中文字符占比<40%或过短时自动fallback到人话模板。

### 关于 smollm2 离线能力的诚实定位（写死，别再前后矛盾）

- smollm2-135m + loveai-core-v2 LoRA：**能加载能生成，但输出质量不稳定**，适合做离线兜底"别完全死掉"，**不指望它说出像样的恋爱话术**
- 真正的体验靠**填API Key走云端大模型**（hy4/deepseek/glm），这是主力
- 离线兜底质量门保证用户看到的永远是人话，不是乱码
- 以后要提升离线质量，方向是：用 finetune.py 重新蒸馏训练（过滤安全套话REJECT_PHRASES那条已有），不是调打包参数

### 安全套话/无限制人设（重申，别丢）

- system prompt 已是"情侣之间没有任何禁忌，亲密的、暧昧的、色情的话都可以说"
- 蒸馏训练时 REJECT_PHRASES 过滤"我不能/作为AI/建议咨询"
- 云端模型回复后，前端展示前必须再过一遍敏感词过滤，不能让"作为AI"出现在用户看到的回复里

## 2026-10-04 晚 需求补充（用户逐题问答整理）

### 核心定位
- 这是一个**恋人辅助攻略系统**，不是聊天机器人
- 软件**一直运行不下线**，作为后台辅助工具
- 核心灵魂是**游戏系统**，代聊是工具

### 启动逻辑
1. 打开软件 → 直接大窗口（主界面）
2. 关闭主窗口 → 桌宠才出来（桌面精灵）
3. 第一次打开要有**新手引导**（不然别人不知道是干嘛的）

### 桌宠功能（关闭主窗后）
- 实时监听微信消息，弹出来提醒
- 可以拖到屏幕任何位置
- 有不同的表情动作
- 点它弹快捷菜单
- 帮我回答问题、咨询疑惑
- 语音转文字帮我回复

### 后台持续运行做的事
- 实时监听微信新消息，自动给回复建议
- 每隔一段时间自动更新好感度/任务状态
- 后台自己学习我的聊天风格
- （还有更多，继续补充中...）

### 主界面布局
- 左边导航栏：聊天分析、情感咨询、人物档案
- 右边：任务面板（可展开）
  - 主线任务（就是等级升级：陌生人→...→终身伴侣）
  - 阶段任务
  - 限时任务（自动生成）
  - 任务奖励：不是虚拟金币，是**现实中对方给的东西**（检测聊天记录里对方答应给你什么，就生成对应任务，完成了就拿到）
- 备忘录功能（在任务面板旁边）：
  - AI自动整理对方的喜恶（不吃香菜/喜欢什么/雷点）
  - 可以手动编辑
- 左下角：设置
- 多角色切换：**根据微信聊天窗口自动切换**——我在微信里点开谁，软件自动切到那个人的档案
- 成就墙：作为小彩蛋，不放在显眼位置

### 任务系统补充
- 任务奖励源自现实：检测到聊天里对方说"下次请你吃饭"，就生成任务"拿到饭约"，完成了就算奖励到手
- AI实时检测聊天内容，自动生成新任务

### 聊天分析页面
- 对方言外之意是什么
- 我该怎么回复（3条建议）
- 我回复之后的后果概率（好的可能/坏的可能）
- 现在是什么局面（当前阶段/对方情绪/关系状态）
- 需要做什么
- 做了以后会怎么样
- 为了达成任务目标，具体怎么操作（教程）
- 这种情况该怎么办（因事制宜的攻略）

本质就是：**一个恋爱游戏系统，教用户怎么谈恋爱**。

### 情感咨询页面（两个模块）
**模块一：对象视角咨询（私教模式）**
- 站在对方（任务对象）的角度，分析你现在该怎么做
- 比如："如果我这么做，她会怎么想？"
- 相当于一个懂她的私教老师

**模块二：自我成长咨询**
- 内置用户档案（你的性格/优点/雷区）
- 告诉你自己该怎么改变、怎么提升
- 详细教程：你这种情况容易踩什么坑，该怎么改
- 想不明白的事可以直接问

### 人物档案页面
- 基本信息（生日/职业/喜好/雷点）
- 18维度好感度雷达图
- **心理学侧写**：不是简单的信息列表，是一个完整的人物描述
  - 完整到什么程度？可以导入数字世界变成一个真正的"分身"
  - 也就是：AI足够了解这个人的性格/说话方式/行为模式，可以模拟她
- 聊天记录总结：不用给用户看，放后台数据库就行
- 关系时间线：和勋章等级好感度挂钩，不用单独展示

### 数字分身的用途
1. **AI对抗预测**：模拟对方会怎么反应，回复什么好一点
2. **行为分析**：分析对方某个行为背后的意思
3. **风险概率**：我选A方案还是B方案，各自成功概率多少
4. **量身定做任务**：根据这个人的特点，定制专属任务和引导方向
5. **挂钩等级/好感度**：数字分身的分析结果，直接影响好感度和等级
6. **实时制定任务**：根据当前情况，动态生成新任务

### 立绘系统
- 每个对象专属Q版立绘
- 好感度变了/对方心情变了，立绘表情跟着变
- 立绘怎么来的：
  - 谈的过程中，任务会引导用户索要照片
  - 聊天记录里自动爬取对方发的照片
  - 用照片AI生成Q版立绘

### 成就勋章系统
- 勋章越多越好：达成什么成就给一个，升到什么等级给一个
- 勋章是**用户的永久成长记录**——换了任务对象也在，代表你自己的成长
- 等级随关系标签实时更新，但勋章一直在
- 展示位置：作为彩蛋放在某个地方，但不能太隐蔽（比如左下角设置里，或者主界面某个小角落）

### 多对象管理
- 可以同时聊好几个对象
- 每个对象相互独立：独立的档案/好感度/任务/立绘
- 切换方式：根据微信聊天窗口自动切
- **英雄立绘墙**：展示所有对象的立绘
  - 和勋章墙放在一起
  - 作为彩蛋展示，但不要太隐蔽
